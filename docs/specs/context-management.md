## 2. 功能需求

### FR-1 · 注入作用域与估算清单一致（CM-A2）

1. 对任一 `--target`，**注入写入的文件集合**必须等于**体量估算计入的文件集合**：清单同源于契约层 `PACK_CONTEXT_AUX_FILES`，禁止任一消费方按自己的子集计算。
2. 现状差异须显式：`apps/cli/src/commands/sync.ts` 的作用域清单当前不含 `PLAYBOOKS.md`（登记为 A-1）。⚠️ **本条的实施会改变注入产物字节 ⇒ A 级变更**：owner 裁定 → 附录编号 → `schemaVersion + 1` → 先改 golden 再改实现。
3. 未签收前保持现状，且现状必须在摘要/注释里可读出「此处比估算少一项」，不得静默。

### FR-2 · 体量读数口径成文（CM-A3）

1. `SizeEstimate` 的每个读数只回答一个问题，并在契约注释里写全四要素：**分子／分母／单位／复算方式**。
2. 三个读数的口径：`footprint.bytes` ＝ 落盘量；`perTarget.approxTokens` ＝ 某平台实际读入量的估算；`density` ＝ 受管量 ÷ 覆盖资产数（分母口径以 `context-density.md` 的裁定为准）。
3. 只改注释与文档，不改任何数值语义；若未来要改口径，必须带口径版本号（否则新旧读数不可比）。

### FR-3 · 四套文件状态词表的语义映射（CM-A6）

1. 注入五态、一致性四态、核验六态、退役四态**不合并**，只建立唯一映射表：给定「注入态 ＋ 一致性态 ＋ 核验态 ＋ 退役态」的组合，映射到**唯一**的「展示用状态 ＋ 建议处置」。
2. 映射表必须**闭合**：出现未覆盖的组合即判红（不得默认落到「正常」）。
3. 映射表是展示与建议的来源，**不改变任何判定逻辑**；四套词表的原义保持不变。

### FR-4 · 上下游闭合棘轮（CM-C3）

**状态：已落地（v1.1，2026-11-05）**。基线 `docs/context-check-baseline.json`，判红口径见 [context-governance.md](./context-governance.md) §7.2。

1. `pnpm context:check` 的 C-5 计数写入机器可读产物，并以上一轮值为**上界**：新增一条「声明了下游但对方未回指」的登记即红，并给出差值。
2. 上界只降不升：消除一条后，上界随之下调；上调必须显式改基线并留痕。

### FR-5 · 退役动作表与基线反向（CM-C5）

1. 规范化的退役分三类：**资产**（如字体文件）、**契约**（字段与 schemaVersion）、**文档**（规格与台账）。每类必须写明「谁签收、是否需要 A 级流程、删除前需要哪些证据」。
2. 基线登记只允许精确条目（禁通配）；基线项消失时由反向检查报「该清理」，不得静默留着。
3. 任何退役动作都不得产生计划外字节变更；涉及产物的退役一律走 A 级。

### FR-6 · 本地与 CI 同源（CM-C6）

**状态：已落地（v1.2，2026-11-05）**。本地侧接在 `scripts/hooks/pre-commit` 的闸四，口径见 [context-governance.md](./context-governance.md) §7.3。

1. 同一校验入口必须在**提交前**与**CI**各跑一次；CI 侧已接 `context:check`（见 `.github/workflows/ci.yml`），本地侧接入方式不限（钩子或脚本）。
2. 本地侧失败必须阻断提交，并给出判据编号（C-x）与文件位置。
3. 本地侧不得放宽判据，也不得用 `continue-on-error` 之类的方式把红变黄。

## 3. 边界与异常

- **FR-1 与 A-1 是同一件事的两面**：A-1 是变更申请，FR-1 是判定条件。签收后两者同时关闭；未签收时 FR-1 只提供「怎么判」，不提供「怎么改」。
- **FR-3 不得代替原状态机**：四套词表的判定代码不改，映射表只在读取侧生效。出现「映射表要求处置 X、原状态机判定 Y」的冲突时，以原状态机为准并登记映射表缺陷。
- **FR-4 的上界不是目标**：上界的作用是防止恶化，不承诺降到 0；降到 0 需要逐条补上下游登记。

## 4. 验收标准（pass／fail 二值）

| ID       | 判据       | pass 条件                                                                   |
| -------- | ---------- | --------------------------------------------------------------------------- |
| UT-CM-01 | 作用域一致 | 任一 target 的注入文件集合 == 估算计入集合，逐文件断言；改坏任一侧即红      |
| UT-CM-02 | 口径四要素 | `SizeEstimate` 每个读数的注释都含分子／分母／单位／复算方式，缺一项即红     |
| UT-CM-03 | 映射表闭合 | 枚举四套词表的全部组合，每组都能映射到唯一结论；出现未覆盖组合即红          |
| UT-CM-04 | 棘轮       | 新增一条单向登记 ⇒ `context:check` 红并给出差值；消除一条 ⇒ 上界自动下调    |
| UT-CM-05 | 退役动作表 | 任取一个退役提案，表能判定「签收人／是否 A 级／需哪些证据」；三类齐全       |
| UT-CM-06 | 本地闸同源 | 故意改坏一行 `COMPAT_MATRIX.reads` ⇒ 本地提交被拦，提示含判据编号与文件位置 |
