## 1. 目标与用户价值

- PRD 的画像表里有三类用户且诉求**互相矛盾**：新手要「照做」，独立 coder 要「挑」，Tech Lead 要「定义别人怎么判断」。**本文成稿时（2026-10-03）**的界面只有一套——它同时服务三者，因此谁都不舒服：新手一进来面对的是 **109 条术语 + 21 条提示词 + 5 个模块导航 + 组包向导**（§3-1 现测），专家被迫逐条手点、没有批量与键盘优先路径。
- 分析文 §5 给的不是「新手模式开关」，而是**按模块维护的阶段向量** + 五条不可违反的披露硬约束。两者的区别是决定性的：开关假设用户「要么新手要么老手」，向量承认**同一个人在提示词上是作者、在 Skill 上是刚扫第一次的新手**（§4 概念条）。
- 六项能力里最省的是 C1/C3/C6，因为它们**不是新建而是接线**——但「零件都在」这句话**本文成稿时（2026-10-03）**只对工作树成立、**对提交树不成立**（§3-2、§3-3），所以本文件把它列为前置而不是收益。这条更正比原判断更重要：照着「已存在」排期会排出一张空表。
- 反方向的价值也要写：**CP4 的边界单列**（§8.2 待裁①之外最容易被下轮越界的一条）。`m4-playbook.md §2 Out` 把「自动从日志提取候选」判为不做，理由是「全仓零实现且质量不可判定」；本文件采分析文 §5.4 的收敛形态——**确定性提取**（用户显式标记或选中段落点按钮），并把「要引入 LLM 推断必须先有一次独立 B 级裁定 + 明确质量判据」写死在 FR-9.3。（**2026-10-22 现测同值**：复算命令与判定口径见 `m4-playbook.md` FR-5.2 —— 本文件不复制命令，避免两处漂移）

## 4. 数据与核心概念

- **阶段（F0–F3）**：F0 跟随者／F1 实践者／F2 作者／F3 定标者，定义与四条毕业信号**单源在分析文 §5.1 表**，本文件只写它落到本仓字段与事件名上的形态（§3-6、§3-8 的更正都在这里生效）。
- **阶段向量**：`{prompts, terms, skills, flows, packs} × F0..F3`，**按模块**维护、不是全局级别。用户看到的界面 = 当前模块那一格的值；「一个数概括一个人」在本文件里是被拒绝的方案。
- **三维的诚实说明**：分析文写「(用户 × 资产类型 × 任务) 三维」，本产品**没有用户维度**（本地单用户、无账号）。所以实现上只剩两维（模块 × 阶段），第三维的实际承担者是**项目**（`projects` 表）：同一模块在不同项目可以不同阶段吗？本文件裁**否**（向量按模块全局一份），理由是 §3-8 的信号源里没有可靠的「按项目意图」维度，硬做会变成伪精确——这一条登记为待裁②，不代 owner 定。
- **单调递增 + 可显式回退**：毕业信号只会把某模块的**上限**推高（`maxReached`）；界面当前视图（`currentView`）可以低于上限（用户主动切「专家视图」或「跟随视图」）。两者必须分开存：合并成一个字段就同时失去了「防止手滑降级」与「一键越级」两条。
- **越级 vs 重置**（两个动作，绝不共用一个字段）：**越级** = 把 `currentView` 推到 `maxReached` 或更高、按模块记忆；**重置** = 清空整份向量、回到「无任何信号」的推导起点（设置页一条动作，文案须明写「不影响你的任何数据，只影响界面默认折叠状态」）。
- **渐进披露 ≠ 隐藏**：规则 1/2 把边界钉死——**只有排序、预填、折叠默认值的差别**，「查看全部」一键可达；任何阶段都必须看到失败、漂移、冲突。实现上每条披露规则必须成对写「默认值」与「越级路径」，只写前者视为违反本 FR。
- **时效语义（freshness）不是一个字段四种用法**：按分析文 §3.2 推论，四类资产各自表达——提示词「最后验证于」（可由 `updated_at` 起步，但**语义不同，须独立列**）、术语「生态版本」、Skill「上游活跃度」（`skills.remote_ref`／`remote_tree_hash` 已在 0005，是现成锚点）、流程「慢变量」可不显示。**共同戒律：不得用一个 `level` 字段把四者折成一个数**（那是「把同一个笼子换个牌子」）。
- **推荐 v0**：规则表 + 阶段向量 → ≤3 条下一步；无模型、无学习、无个性化画像。它的可测性恰恰来自无聊（固定剧本 → 固定集合，快照断言）。

## 5. 功能需求

### FR-1 · 2-1 资产 `audience`／`freshness` 字段（判级 B，停在 B）

1. 两列**只加在需要它们的那几张表**，不做「五类资产齐列」的美化：`audience` 进 `prompts`／`terms`／`skills`／`flow_templates`（披露层要用）；`freshness` 进 `prompts`／`terms`／`skills`（`flow_templates` 是慢变量，加列只制造一个永远不变的数）。
2. **向前兼容是硬条件**：新列一律 `NULL` 默认（旧行不改写、不回填）。若某列需要 CHECK 值域，走 §3-7 的 0004 重建形制并在迁移文件头照抄那句「SQLite 不能 ALTER CHECK 约束」的理由；能用可空无约束列的，一律走 0005 形制（**一条 ALTER，成本差一个量级**）。
3. `audience` 与权限**无关**：它只影响默认排序与默认折叠，任何人任何时候都能看到全部（规则 1）。§6.6 把这句写成不变式，因为它是最容易被下一轮「顺手加个新手屏蔽」破坏的地方。
4. `freshness` 的**值域待裁**（§8.2①），因此本 FR 只钉语义形状、不钉字面量：提示词=最后验证于（时间戳语义）、术语=生态版本（版本串语义）、Skill=上游活跃度（可由 `remote_tree_hash` 变化推导，不新造轮询）。
5. **不进 pack 契约**：`audience`／`freshness` 一律不出现在 `manifest.assets[]`、不进 `selection`、不进 lock。一旦要进，判级立刻升 A（分析文 J2 行自陈），须走 golden 重基链——本文件明确把它关在门外。
6. UI 四类资产各一条断言（分析文 2-1 的门禁判据原文「四类资产的时效展示各有断言」），且**缺席即不显示**（不显示「未知」以外的占位，也不显示 1970 年）。

### FR-2 · 2-2 CP1 成长阶段机（本项的心脏）

1. 判定 = **从信号派生**，不存「阶段」这个事实本身：存的是 `maxReached`／`currentView`／显式覆盖（FR-3），阶段值由台账事件 + 既有表算出。**派生优先**的理由：可复算、可重置、可解释（规则 3 要求「为什么你现在看到这个」能被答出来）。
2. 四条信号的取数口径逐条钉（§3-6、§3-8 的更正在此落地）：
   - **F0**：注入 ×1（`injections` 有行 **或** 台账 `injection_confirmed`）＋ 某阶段清单勾完（`project_check_states` 按 `(project_id, stage_name)` 计数 ≥ 该阶段项数，项数取 `projects.stages_snapshot` 而非当时的模板——模板会改）。
   - **F1**：`asset_updated` ≥1（**台账，今天无源**）＋ `flow_template_run` 覆盖 ≥2 个模板 id（**台账，今天只能看到「建项目时选了哪个」**）。
   - **F2**：`asset_created` 且 payload 里 origin 标记为非种子（**判据落 `payload_json.origin`，不落表列**，理由见 §3-6）＋ `pack_exported` 且 `standard_packs.name != 'default'`。
   - **F3**：同一 `pack_id` 被 ≥3 个不同 `project_path` 注入（`injections`，`pack_id IS NOT NULL` 前置）；团队共享分支留空（属 M7=RF5）。
3. 判定服务住在 `services/growthService`（分析文 §4.10 点名的四个服务之一）——**硬依赖 `service-layer.md`**，且它同时依赖 `local-event-ledger.md` 的 `LOCAL_EVENT_KINDS`。两个前置未落地时本 FR 只能以「两支 SQL + 全表扫描」的退化形态存在，届时须明写退化，不许声称已实现。
4. 模块归属映射要显式一张表（`asset_updated(prompt)` → prompts 模块；`stage_advanced` 属 flows 还是 packs？本文件**不代裁**，登记 §8.2③）。
5. 阶段机**只读**：它不写业务表、不改资产、不触发注入。任何「因为你是 F0 所以把你的包改成默认」的动作都不属本 FR。

### FR-3 · 单调、回退、重置三件事

1. 单调：`maxReached` 只增不减；删除资产／清空台账**不降级**（避免「今天手滑降级了」的挫败，分析文 §5.1 决定 2）。
2. 越级：任意页面一处「切到专家视图／跟随视图」，按模块记忆 `currentView`；越级不改 `maxReached`。
3. 重置：设置页一个动作，同时清 `maxReached`／`currentView`，并**在文案里说明会重新出现升级卡片**（否则重置变成「关掉打扰」的入口，与规则 5 冲突）。
4. 存储位置建议 `app_meta` 一个 JSON 值（形制同 `telemetryAskState`，§3-11），**不新建表**——它是一份五个键的向量，不值得一个表；但这条属实现选择，登记 §8.2②。

### FR-4 · 升级时刻 = 一次性卡片，不是静默切换

1. 触发点只在**任务完成后**：注入成功／某阶段清单清空／首次导出。不做「后台重算后弹窗」。
2. 形制复用 `TelemetryAskCard`（`{askState, onChoose}` + `unset/accepted/declined` 三态 + declined 后不再出现，§3-10），**不新造组件、不新造交互语言**。文案示例走 i18n（FR-8 的命名空间）。
3. 每张升级卡必须能被「为什么」解释：卡上带一处展开，写明触发它的那条信号（规则 3 与 FR-2.1 的派生性在此合流）。
4. 拒绝后不再打扰 = 与遥测卡**不同的标记键**（两者独立三态，不可共用一个 `askState`，否则用户拒了遥测就永远看不到升级）。

### FR-5 · 2-3 CP3 渐进披露层（五条硬约束）

1. **规则 1 永不隐藏数据**：只有排序／预填／折叠默认值三种手段，每条手段必须配一条「查看全部」一键可达路径，且该路径在每个阶段都可用。
2. **规则 2 永不隐藏错误**：失败／漂移／冲突在任何阶段都完整呈现。本条是**否证用例最多的地方**：F0 视图下必须有一条用例断言「冲突仍然可见」。
3. **规则 3 阶段可见可解释**：界面永远有一句「为什么你现在看到这个」，可点开。
4. **规则 4 一键越级 + 按模块记忆**（FR-3.2）。
5. **规则 5 升级不打断**（FR-4）。
6. 分页差异默认值的**单源在分析文 §5.3 表**（`/library`／`/terms`／`/packs/new`／`/projects`／冲突处置 五行），本文件不复制表格正文，只做两件事：① 每行必须落成 ≥2 条断言（越级可达 + 错误不吞）；② 两处按现测更正——术语「只显示第 1 站」的**总站数是 9 不是 4**（§3-4）；冲突处置「推荐：保留本地」按队列 ㉕ 的 (a) 案**只改 Web 预选**，CLI 的 `--yes` 保持无交互语义，两者默认可不同但须同屏如实标注（**㉕ 仍是待裁，本文件只是把建议写进来**）。
7. 披露只作用于**界面**：注入产物恒为全集（§3-13 的事实），本文件不允许出现「F0 用户注入出来的包更小」这类隐含承诺。

### FR-6 · 2-4 CP6 成长面板

1. 接位：既有飞轮卡片位（`FlywheelCard` + `GET /api/stats`），**不动首启三步向导**，不改 `OnboardingBar`（分析文 §11 对照表明写这条边界）。
2. 内容：四阶段进度（按模块）、飞轮圈数（沿用既有口径：同项目「导出→注入→回流」去重计数）、本机统计摘要（**取台账聚合，不新造第二个聚合端点**）。
3. 清空事件后数字必须回落（分析文 C6 的机判验收），且回落 ≠ 阶段降级（FR-3.1 的单调性在这里接受检验：面板数字回落、`maxReached` 不动，两者都要断言）。
4. 隐私面：面板只读本机；任何数字不得出现在遥测三事件里（与 `local-event-ledger.md` FR-6 同一条承诺）。

### FR-7 · 2-5 CP2 推荐引擎 v0

1. 输入 = 阶段向量 + 资产标签（`audience` 在此第一次真正被用上）；输出 = **≤3 条**「下一步做这个」。
2. 可测性三件：固定剧本 → 推荐集合确定（快照断言）；**空库不推荐**（一条独立用例，禁止用「默认推荐种子」填空——那是把推荐变成广告）；每条推荐必须带理由（规则 3 的延伸：能说出「因为你在这模块是 F1 且你还没导出过」）。
3. 推荐**不自动执行**任何东西：不替用户组包、不替用户注入、不改选择。点击才发生动作。
4. v0 是规则表，不是算法：新增一条推荐 = 改一次表 + 改一次测试，**禁止**引入打分函数、相似度、任何「智能」措辞。

### FR-8 · 2-6 CP5 教学内容内嵌（判级 C）

1. 每个 FR 页面**至少一处**教学锚点（分析文 C5 的机判口径），锚点 = 一句话「为什么」+ 可展开。
2. 文案**全部进 i18n 命名空间**，不得硬编码在组件里。与 `entry-budget.md` FR-1 的耦合是显式的：该文件把 `zh.ts` 按路由拆 8 份，本 FR 的新文案必须落进对应命名空间文件，**不得落进 `zh.common`**（否则同步加载面长成第二个 `zh.ts`，收益归零——这条在 `entry-budget.md` FR-3.2 已有断言，本 FR 引用它）。
3. 判级 **C**（纯文案与展示），但**排在 2-3 之后**（依赖披露层给出的阶段视图，否则「教学」变成对所有人讲同一句）。

### FR-9 · 2-7 CP4 复盘候选提取（边界条款）

1. 形态 = **确定性提取**：用户在日志里显式用约定标记（如 `[[术语]]`）或选中段落点「提为候选」。规则必须可复算：同一段文本两次提取结果相同。
2. 候选 → 草稿 → **人工确认才入库**；「不确认则不入库」是分析文 C4 的机判验收，必须写成一条独立断言，且不得被任何「自动接受」开关绕过。
3. **CP4 边界单列（本文件最硬的一条）**：`m4-playbook.md §2 Out` 不推翻。要引入 **LLM 推断式提取**，须先具备两件事——① 一次**独立的 B 级裁定**（不夹带在任何 RF 阶段里）；② 明确的**质量判据**（可测的准确率口径，不是「看起来不错」）。二者缺一，实现即视为越界，评审须直接拒。
4. 与既有回流链的分工：读链（`reflow-origin`，§3-12）已存在，本 FR 只加「候选」这一层，**不改**既有回流语义、不动 `FlywheelStatsOut.reflows` 的口径。

## 6. 边界与异常

### 6.1 前置不是建议：三件事任一未做，RF2 就是空转
① §3-3 的六个未入库零件（含 17 个 untracked 文件里的产品代码）必须先由它们的作者入库——**入库笔不是我这一轮能做的，我也不 stage**；② `local-event-ledger.md`（1-5）必须落地，否则 F1 两支信号无源（FR-2.2）；③ `service-layer.md`（1-1）必须落地，否则 `growthService` 无处安放。这三条都在 PRD §10.2 的「依赖 1-5」里，本文件把它拆成可核的三件。

### 6.2 「渐进披露」最大的失败模式是变成隐藏
一旦某条规则写成「F0 不显示版本历史」，它就越界了（规则 1）。可执行的判据是：每条披露规则的实现里必须能找到「查看全部」那一支的测试；找不到测试 = 没实现规则，实现了隐藏。

### 6.3 阶段判据不可复算就等于没有
分析文给的 `source != seed` 在今天**一句都落不了地**（§3-6：四类资产的来源字段三套不同、`seed` 不是任何取值）。本文件因此把「非种子」判据落到 `payload_json.origin`，并要求它由**服务层写入时**盖章（一处），而不是事后从 `seed_hash` 反推——`seed_hash` 只证明「曾经与种子同形」，删种子后它就变成沉默。这条必须写进实现，否则 F2 的判据会在下一次 reseed 后漂移。

### 6.4 D28 的否证触发器（本文件的存亡条款）
PRD 附录 D 的 **D28** 采纳 RF2 时配了否证触发器：**分析文 §10-1 的五人走查**。走查若证伪「阶段模型对真实用户有意义」，则**撤回 CP1／CP2／CP6，只保留 CP3 + CP5**（披露硬约束与教学内嵌即使没有阶段机也成立）。走查排在 RF2 开工**之前**，已登记进队列。⇒ 本文件写 CP1/CP2/CP6 的三份 FR 时一律带「否证后可整体移除」的形状：它们只读信号、只改默认值、只加卡片，**不改任何数据结构不变量**，所以撤回成本接近零。这条设计约束是刻意的，不是巧合。

### 6.5 同名异物：「飞轮面板」
`dev-plan §15.5` 第 6 行已裁定过一次同名异物：tasks 变体备案里的「飞轮遥测面板」指**未做的遥测看板**（归 P2），代码里 `FlywheelCard.tsx` 是**已交付的本地五项统计卡片**。FR-6 接的是后者。本文件的措辞一律写「成长面板（接 `FlywheelCard` 位）」，**不得**简写成「飞轮面板」，否则下一轮会按「P1 该有面板」重复排工或按「面板归 P2」误判已交付功能是缺陷。

### 6.6 阶段不是权限，也不是筛选器
`audience`／F0–F3 都不构成访问控制。任何「F0 看不到某资产」的实现都是 §6.2 的越界；任何「按 audience 过滤搜索结果」同样越界（默认过滤 = 隐藏）。规则 1 的精确表述是：**差别只发生在默认值上**。

### 6.7 第四套状态词汇的风险（与另三份文件同族）
仓里已有 `INJECT_STATUSES`／`SYNC_STATES`／`retirement` 四态三套词汇（`entry-budget.md` FR-7 正在收敛前两套）。F0–F3 是**第四套**，且它语义上完全无关（那是成长，这是写入结果）。因此：阶段值的常量名必须显式带 `GROWTH_` 前缀、不得进注入报文、不得进 lock、不得进 manifest。这句边界不写，一年后一定有人拿 `status` 复用。

### 6.8 隐私：与遥测三事件「不同名、不同表、不同出口」
沿用分析文 §5.2 末段与 `local-event-ledger.md` FR-2/FR-6 的三不同。本文件额外承担一条：**阶段本身永不出网**。设置页两节并排的呈现由台账那份文件负责，本文件只保证「成长面板与推荐引擎产生的所有数都来自本机台账 + 本机表」，并把它写成断言。
