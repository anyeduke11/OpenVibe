## 1. 目标与用户价值

社区新用户（D1 画像，P0）装完产品的第一印象即双钩子（D2）：**3 条命令、5 分钟内**，在自己机器的测试目录里看到 `CLAUDE.md`/`TERMS.md`/`CHECKLIST.md` 被真实注入、能跑一次漂移检测——而不是面对一个空库。

## 2. 范围

| In（MVP） | Out（→P1.1/P2） |
|-----------|------------------|
| 预置演示标准包（首启自动组装） | 交互式 onboarding tour 覆盖更多页面 |
| 首启向导 ≤3 步、可跳过、真实副作用 | 账号/引导邮件等一切外部触达 |
| 飞轮统计面板（本地统计） | 面板数据上报（遥测仅三类白名单事件，见 design §11.5） |
| 遥测开关入口（设置页，默认关） | |
| 成长面板（C6）的**接入位** = 飞轮卡片（FR-5，v1.2 加） | ❌ 改向导的步数与形制（分析文 §11 明写「不动其 3 步向导」；C6 只许往飞轮卡片里接） |

## 3. 功能需求（FR）

### FR-1 预置演示标准包
1. 首启（DB 初始化 + 播种完成后）自动组装名为 `default` 的标准包：selection = 种子精选提示词全部（20 条）+ 种子术语全部（≥100）+ 「个人轻量流」模板；targets = **全部六个 adapter**（claude-code / cursor / generic-agents / codebuddy / trae / minicode，D7+D9）；version = `1.0.0`；完成一次目录导出登记（走 m6a 正常导出通道，形成导出历史）。
2. 组装结果**可删可重建**：它是普通 StandardPack，用户删掉后设置页提供「重建预置包」；用户改过则重建跳过并提示（复用种子升级的「用户改过则跳过」规则）。
3. `openvibe sync` 缺省包解析规则不变（项目登记优先）；预置包只是「存在且可用」，不劫持任何默认行为。

### FR-2 首启向导
1. Web 首启判定：DB 无项目且无向导完成标记 → 工作台顶部出现向导条（非全屏遮挡，可随时点「跳过」，跳过即写入完成标记）。
2. 三步，每步**真实副作用**红线（验收 3）：
   - 步①「你的资产库已就位」：展示种子统计（提示词 / 术语 / 模板三条**真实计数**，取自 `GET /api/settings`，不写定值以免双源漂移），链接可点进真实列表页；
   - 步②「看一个标准包长什么样」：打开预置包预览（真实 preview API 返回的文件树与内容），非截图；
   - 步③「注入试试」：展示可复制的 `npx openvibe-cli sync <测试目录> --pack default` 命令 + 一个建议的临时目录路径；用户执行后回向导点「我已注入」→ 向导弹 `diff` 命令引导体验漂移检测，完成。
3. 向导完成/跳过状态持久化（app meta）；重置入口在设置页（配合演示回归测试）。
4. **步骤③自动确认（D11，2026-09-20 裁定）**：向导轮询（或用户点「我已注入」时）检测测试目录 `<dir>/.openvibe/pack.lock.json` 是否存在——存在即自动点亮「注入完成」并展示 diff 引导；手动按钮保留为降级路径（目录不可读/用户换了目录时）。

### FR-3 飞轮统计面板
1. 工作台顶栏常驻卡片：五项本地统计——资产数（M1+M3+M2 条目）、标准包数（导出次数）、注入次数（injections 记录数）、回流条数（linkedAssetIds 非空的日志数）、**飞轮圈数**。
2. 飞轮圈数定义：同一项目上「存在导出包 → 有注入记录 → 有 ≥1 条回流资产」记 1 圈；按项目去重计数。数字口径在卡片 tooltip 说明。
3. 全部本地计算（SQL 聚合），不参与遥测。

### FR-4 遥测开关入口
1. 设置页「匿名统计」区：默认**关**，文案列明三类事件白名单与「关闭时零外联」承诺，一键开关即时生效；实现规格在 design.md §11.5。
2. **一次性 opt-in 询问（D13，2026-09-20）**：首次注入成功（向导③ lock 检测通过，或 CLI 首次 sync 成功）→ 展示一次性卡片「开启匿名统计？」，附三类事件白名单与零外联承诺，按钮「开启 / 暂不」；选择持久化本地标记（与 CLI 共享 `telemetryAskState`：declined 永不再问，accepted 同步设置页开关为开）；询问本身零网络请求。

### FR-5 成长面板（C6）的接入位 = 飞轮卡片，不是新页面（v1.2 加，对应 RF2 的 2-4 行；**阶段模型与判据的细则单源在 [`growth-path.md`](./growth-path.md)**，本文件只管位置与首屏预算）

1. **接入位置是实名的、可复算的**：现测飞轮面板 = `apps/web/src/components/onboarding/FlywheelCard.tsx`（组件签名 `FlywheelCard(props: FlywheelStatsOut)`），由 `AppShell.tsx` 在顶栏挂载，且是**条件挂载**（`stats.data !== undefined` 才出现），数据源 `GET /api/stats` → `FlywheelStatsOut`。复算：`grep -rn FlywheelCard apps/web/src` ⇒ 命中三处（AppShell 的 import、挂载行、组件定义）。分析文 §11 对开箱体验那句「不动其 3 步向导，仅在飞轮面板处接入 C6」落到代码上就是**这一个挂载点**。⇒ 成长面板**不新建页面、不新建第二张顶栏卡片**；`FlywheelStatsOut` 若因 C6 增键，属 [`output-validation.md`](./output-validation.md) 的出参断言面，**判级按 §0.3 现算，静加键不许**。
2. **向导的三条红线原样不动**：FR-2 全段（≤3 步、每步真实副作用、可跳过且跳过后不再出现）与验收 1／2／2b／3 逐字保留。**为什么要把这句写进规格**：C1 的阶段机（F0–F3）天然想往首屏加一条「你现在是第几级」，而首屏**已经**是向导条 + 飞轮卡片 + 注入状态三件套（`AppShell.tsx` 的顶栏注释自陈这是 dev-plan §5.1 的常驻三件）。再加一层披露，D28 的「阶段可见可解释」就地变成「首屏更挤」——而队列 ㉝ 的 §10-1 否证触发器（五人走查若把阶段切换读成功能阉割，即撤回 CP1/CP2/CP6）判定的**正是这个观感**。所以本 FR 的第一条不是「怎么加」，是「加在哪、不许再加第二处」。
3. **`injection_confirmed` 是 MT2 的右端点，但 MT2 今天两端都没有地基**（本 FR 最重要的实测更正，且**不在本文件自裁**）：分析文 §9.1 的 D2 行（PRD §10.0 右列改称 **MT2**）定义「从首启到『项目目录出现第一个产物文件』的墙钟时间」，目标形态写「首启事件 → `injection_confirmed` 时间差；进成长面板」。**现测两端不对称**：
   - **右端可用**——`injections` 表本就带 `injected_at`（复算 `grep -n -A6 'CREATE TABLE injections' packages/core/src/db/migrations/0001_init.sql`），「第一个产物文件出现」的时刻**不必等台账**。
   - **左端无处可取**——`app_meta` 建表只有 `(key, value)` 两列，**没有任何时间戳列**（复算 `grep -A4 'CREATE TABLE app_meta' packages/core/src/db/migrations/0002_app_meta_telemetry.sql`），而向导标记 `onboardingDone` 存的是**布尔**（`packages/core/src/repos/appMeta.ts` 的 `APP_META_KEYS` 三键之一）。⇒ 「首启时刻」在今天的 schema 里**根本没有存储**；台账的 `kind` 闭集（[`local-event-ledger.md`](./local-event-ledger.md) FR-2，含其扩到 13 项的提案）里**也没有首启/安装类事件**。
   - **三条出路登记为待裁**（① 见 §6）：(a) 给台账加一个首启类 kind；(b) 新迁移给「首启」配带时间戳的载体；(c) MT2 退化为「首次注入时刻 − 首条资产时刻」这种本机现算的近似。**未闭合前面板不得显示 MT2**（宁缺不假，与 §4.3 的「显示占位而不是 0」同源）。
   - **一条不许走的捷径**：把 MT2 改建在遥测的 `pack_injected` 上（复算 `grep -n 'TELEMETRY_EVENTS = ' packages/shared/src/constants.ts` ⇒ 三类白名单是 `pack_injected`／`flow_template_used`／`project_active`）。遥测**默认关**（FR-4.1），拿它当度量分母等于只给开了遥测的人算指标，与 PRD §10.5「MT1–MT6 全部本机、全部可复算、**不上报**」正面冲突。**同名提醒**：`pack_injected`（遥测）与 `injection_confirmed`（台账）是两个名字、两个面，`local-event-ledger.md` FR-2.2 那条「两集合严格不同名」的断言就是防这一对混淆的。
4. **阶段判据、越级、重置一律指回 `growth-path.md`**，本文件不复制——两处各写一遍阶段定义，就是双源违规（dev-plan §13-8 的同一口径）。本 FR 与那边 FR-6（C6 成长面板）的关系是**位置 ↔ 内容**：那边规定面板显示什么，这边规定它只能长在飞轮卡片这一处。

## 4. 边界与异常

1. 首启组装预置包失败（种子缺失/损坏）→ 跳过组装、记 warning，不阻塞 serve；向导步骤②降级为「去组包向导」链接。
2. 用户在向导中点了「我已注入」但 CLI 未执行 → lock 检测不通过时按钮不点亮，并提示「未检测到 .openvibe/pack.lock.json，请确认命令已执行」（自动确认机制生效，D11）；目录不可读时降级为诚实按钮并提示。
3. 统计面板在数据为 0 时显示占位文案（不是 0），避免「全是 0」的负面首感。
4. 向导在窄屏/移动端允许布局降级但不隐藏跳过按钮。
5. **成长面板与向导同时出现在首屏时的次序**（v1.2 加）：向导条优先、C6 内容不得遮挡「跳过」按钮；两者共存不得把首屏撑到需要滚动才看到主操作。这条是 FR-5.2 的观感红线在异常面的写法——**「首屏变挤」不算异常态，但它必须是可判的**，判法即走查（§10-1），所以规格先把次序写明，免得走查时两边都没依据。
6. **飞轮卡片是条件挂载**（既有行为，v1.2 明确不许改好心的「优化」）：`stats.data === undefined` 时整块不出现。接入 C6 后**不得**改成「先挂空壳再填数」——那会把 §4.3 的「数据为 0 显示占位文案」升级成首屏闪一下假零，属假零禁止面。

## 5. 验收标准（pass/fail）

1. **≤3 条命令 / ≤5 分钟**：干净环境演练（tasks T9 场景）——`npx openvibe-cli serve --open` → 向导三步 → `npx openvibe-cli sync <dir> --pack default`，测试目录出现 `CLAUDE.md`/`AGENTS.md`/`CODEBUDDY.md`/`MINI.md`/`.cursor/rules/openvibe.mdc`/`.trae/rules/openvibe.md`/`TERMS.md`/`CHECKLIST.md` 与 lock 文件。
2. 跳过向导 → 刷新不再出现；设置页重置后重新出现。
2b. 步骤③注入前点「我已注入」→ 不点亮并出现 lock 未检测提示；执行 sync 后（或再点按钮）→ 自动点亮进入 diff 引导。
3. 真实副作用抽检：向导步骤②展示的文件树与 `GET /api/packs/:id/preview` 响应一致（同源校验，非静态图）。
4. 面板数字口径：造 1 项目走完「组包→注入→回流」后飞轮圈数 = 1；删除该项目后圈数回落。
5. 遥测开关默认为关；关闭状态下抓包（或代码审查断言）无外联请求。
5b. 首次注入完成后出现一次性询问卡片；选「暂不」→ 重启/再次注入不再出现（本地标记生效）；选「开启」→ 设置页开关同步为开，且三类事件仍走单出口 `reportEvent()`。
6. **接入位唯一（v1.2 加，判据可复算）**：C6 落地后，顶栏仍只有**一张**统计卡片——复算 `grep -rn FlywheelCard apps/web/src/components/AppShell.tsx` 命中数不因 C6 增加，且 `apps/web/src/components/onboarding/` 下不出现第二张成长/阶段卡片组件；向导**仍是三步**（验收 1 的干净环境演练逐字复跑，步数与每步的真实副作用不得变化）。
7. **MT2 的两端各有一条腿（v1.2 加，含一条负向）**：右端能从 `injections.injected_at` 取到「第一个产物文件出现」的时刻（一支查询即可复算）；左端在 §6 待裁① 闭合前，成长面板**不得显示 MT2 数值**——这一条按「面板上找不到该项」判 pass，**不得用 0 或「—」占位冒充已测**（§4.3 与 §4.6 的同一条纪律）。

## 6. 依赖

- 依赖：m6a（组装/预览/导出）、m6b（sync/diff）、seed-content（种子到位是预置包前提）。
- 被依赖：PRD 1.4 北极星面板口径、T9 干净环境验收场景。
- **FR-5 的上游与单源**（v1.2 加）：PRD §10.2 的 RF2 行 2-4（成长面板）、分析文 §11（「不动 3 步向导，仅在飞轮面板处接 C6」这一句的出处）、分析文 §9.1 的 D2 行（= **MT2**，定义与目标形态**单源在那里**，PRD §10.5 明写度量定义不在 PRD 复制）；[`growth-path.md`](./growth-path.md)（阶段模型 F0–F3、C6 面板内容、§6.4 的 §10-1 五人走查否证触发器）、[`local-event-ledger.md`](./local-event-ledger.md)（`injection_confirmed` 与其 kind 闭集）、[`output-validation.md`](./output-validation.md)（`FlywheelStatsOut` 增键时的出参断言面）。
- **待裁（v1.2 登记一条，不代 owner 裁）**：
  ① **MT2 的左端点「首启时刻」用什么承载**——(a) 台账加首启类 kind（动 `local-event-ledger.md` FR-2 的闭集，那边已判「增删 kind 属改迁移，预判 B」）；(b) 新迁移给首启配带时间戳的载体（B 级）；(c) MT2 退化为「首次注入 − 首条资产」的近似（**改的是度量定义，须回写分析文 §9.1 还是另立一档，也得裁**）。三案的共同代价都是「多一处本机写入」，共同收益是 MT2 第一次有机读源；**在任一案裁定之前，本 spec 的验收 7 那支负向腿生效，面板不得显示 MT2**。
