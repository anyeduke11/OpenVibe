## 1. 目标与用户价值

社区新用户（D1 画像，P0）装完产品的第一印象即双钩子（D2）：**3 条命令、5 分钟内**，在自己机器的测试目录里看到 `CLAUDE.md`/`TERMS.md`/`CHECKLIST.md` 被真实注入、能跑一次漂移检测——而不是面对一个空库。

## 2. 范围

| In（MVP） | Out（→P1.1/P2） |
|-----------|------------------|
| 预置演示标准包（首启自动组装） | 交互式 onboarding tour 覆盖更多页面 |

## 3. 功能需求（FR）

### FR-1 预置演示标准包
1. 首启（DB 初始化 + 播种完成后）自动组装名为 `default` 的标准包：selection = 种子精选提示词全部（20 条）+ 种子术语全部（≥100）+ 「个人轻量流」模板；targets = **全部六个 adapter**（claude-code / cursor / generic-agents / codebuddy / trae / minicode，D7+D9）；version = `1.0.0`；完成一次目录导出登记（走 m6a 正常导出通道，形成导出历史）。
2. 组装结果**可删可重建**：它是普通 StandardPack，用户删掉后设置页提供「重建预置包」；用户改过则重建跳过并提示（复用种子升级的「用户改过则跳过」规则）。
3. `openvibe sync` 缺省包解析规则不变（项目登记优先）；预置包只是「存在且可用」，不劫持任何默认行为。

### FR-2 首启向导
1. Web 首启判定：DB 无项目且无向导完成标记 → 工作台顶部出现向导条（非全屏遮挡，可随时点「跳过」，跳过即写入完成标记）。
2. 三步，每步**真实副作用**红线（验收 3）：
   - 步①「你的资产库已就位」：展示种子统计（提示词 20 / 术语 100+ / 模板 3），链接可点进真实列表页；
   - 步②「看一个标准包长什么样」：打开预置包预览（真实 preview API 返回的文件树与内容），非截图；
   - 步③「注入试试」：展示可复制的 `npx openvibe-cli sync <测试目录> --pack default` 命令 + 一个建议的临时目录路径；用户执行后回向导点「我已注入」→ 向导弹 `diff` 命令引导体验漂移检测，完成。
3. 向导完成/跳过状态持久化（app meta）；重置入口在设置页（配合演示回归测试）。
4. **步骤③自动确认（D11，2026-09-20 裁定）**：向导轮询（或用户点「我已注入」时）检测测试目录 `<dir>/.openvibe/pack.lock.json` 是否存在——存在即自动点亮「注入完成」并展示 diff 引导；手动按钮保留为降级路径（目录不可读/用户换了目录时）。

### FR-3 飞轮统计面板
1. 工作台顶栏常驻卡片：五项本地统计——资产数（M1+M3+M2 条目）、标准包数（导出次数）、注入次数（injections 记录数）、回流条数（linkedAssetIds 非空的日志数）、**飞轮圈数**。
2. 飞轮圈数定义：同一项目上「存在导出包 → 有注入记录 → 有 ≥1 条回流资产」记 1 圈；按项目去重计数。数字口径在卡片 tooltip 说明。
3. 全部本地计算（SQL 聚合），不参与遥测。

### FR-4 遥测开关入口
1. 设置页「匿名统计」区：默认**关**，文案列明三类事件白名单与「关闭时零外联」承诺，一键开关即时生效；实现规格在 design.md §11.5。
2. **一次性 opt-in 询问（D13，2026-09-20）**：首次注入成功（向导③ lock 检测通过，或 CLI 首次 sync 成功）→ 展示一次性卡片「开启匿名统计？」，附三类事件白名单与零外联承诺，按钮「开启 / 暂不」；选择持久化本地标记（与 CLI 共享 `telemetryAskState`：declined 永不再问，accepted 同步设置页开关为开）；询问本身零网络请求。

## 4. 边界与异常

1. 首启组装预置包失败（种子缺失/损坏）→ 跳过组装、记 warning，不阻塞 serve；向导步骤②降级为「去组包向导」链接。
2. 用户在向导中点了「我已注入」但 CLI 未执行 → lock 检测不通过时按钮不点亮，并提示「未检测到 .openvibe/pack.lock.json，请确认命令已执行」（自动确认机制生效，D11）；目录不可读时降级为诚实按钮并提示。
3. 统计面板在数据为 0 时显示占位文案（不是 0），避免「全是 0」的负面首感。
4. 向导在窄屏/移动端允许布局降级但不隐藏跳过按钮。

## 5. 验收标准（pass/fail）

1. **≤3 条命令 / ≤5 分钟**：干净环境演练（tasks T9 场景）——`npx openvibe-cli serve --open` → 向导三步 → `npx openvibe-cli sync <dir> --pack default`，测试目录出现 `CLAUDE.md`/`AGENTS.md`/`CODEBUDDY.md`/`MINI.md`/`.cursor/rules/openvibe.mdc`/`.trae/rules/openvibe.md`/`TERMS.md`/`CHECKLIST.md` 与 lock 文件。
2. 跳过向导 → 刷新不再出现；设置页重置后重新出现。
2b. 步骤③注入前点「我已注入」→ 不点亮并出现 lock 未检测提示；执行 sync 后（或再点按钮）→ 自动点亮进入 diff 引导。
3. 真实副作用抽检：向导步骤②展示的文件树与 `GET /api/packs/:id/preview` 响应一致（同源校验，非静态图）。
4. 面板数字口径：造 1 项目走完「组包→注入→回流」后飞轮圈数 = 1；删除该项目后圈数回落。
5. 遥测开关默认为关；关闭状态下抓包（或代码审查断言）无外联请求。
5b. 首次注入完成后出现一次性询问卡片；选「暂不」→ 重启/再次注入不再出现（本地标记生效）；选「开启」→ 设置页开关同步为开，且三类事件仍走单出口 `reportEvent()`。
