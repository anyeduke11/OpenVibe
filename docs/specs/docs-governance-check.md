## 1. 目标与用户价值

- **一句话**：把「人肉保持一致」换成「不一致即红」。分析文 §8.3 的本章立论：漂移的成因是「文档没有编译期」，不是「人不认真」；所以处置顺序是**先建编译器，再修存量**，否则修完重新开始漂。
- 用户价值是间接的但真实：这个项目对外的头号卖点是「流程与知识可自证」，而它**自己的治理此刻不能自证**（分析文 FP6／PRD §10.1：系统的边界应当是「可自证的」，不是「被信任的」）。治理面一旦说谎，产品叙事就漏。
- **立项依据的口径必须按 PRD §10.4.1 写，不按分析文写**：分析文 §4.11 与 §7 · Phase 0 表 0-4 行都写「已发生 **2** 次计数错报」；PRD §10.4.1 推论 3 的现测是「**4 处计数错报、分 2 类** ＋ 1 次断号 ＋ **18/33 行无就地复核路径**」。本文件采后者。**两处口径不一致是文档间的活漂移，处置 = 在登记里指明采哪个，不是替分析文改字**（分析文按自己 §12 不改既有文档，本文件也不回改它）。
- **一条禁止声称**（队列 ㉜ 的约束已写死）：**不得声称 FP5「治理成本次线性」已被证明**。那需要「复审一行平均耗时」数列，而该数**待人测且明确不可机测**（PRD §10.4.1：它是人的阅读时间，任何脚本给出的数都是编的）。本规格交付的是**校验**，不是**成本证明**。

**「CHECK = 0」这一条不是我的发现**，是分析文 §11 表末行登记的事实缺口：`docs/tasks.md` §1 要求「每 40 轮一份 CHECK 报告」，全仓一条没有。分析文的评语我原文引用其结论而不重复其论证：**一条不执行的规则比没有规则更坏**，它会让人以为被遵守了。⇒ FR-5 必须把「CHECK 段是否存在」做成**可裁定的两种合法态之一**，而不是继续挂着一条没人执行的规则（§8.2 待裁③）。

**三个概念**：

- **计数自洽**：文档里写出的**聚合数字**（「共 33 行」「待裁 6」「已裁已落 18」）与**被数的对象**在同一棵树里能被重新算出且相等。PRD §10.4.1 的实测分布是：33 行队列，净状态六类相加 = 33（**本轮 2026-10-03 再复算过 ✅**；⚠️ **这是 2026-10-03 的点时值，队列增行后即过期** —— **当前值一律现跑**，复算命令见 §7 验收条目 b；口径 = `decisions.md`「净状态」节的六个 bullet 之首数字求和，与表格行首序号数相等；表格行复算 `python3 -c "import re;print(sum(1 for l in open('docs/decisions.md',encoding='utf-8') if re.match(r'^\| [①-㉟]+ +\|', l)))"` ⇒ 33。**别用 BSD grep 跑这个数**——同式它返 21，见 FR-2.4）。**一处要让下一轮读者知道的坑**：按 状态 列前缀自己分类会得到 **5** 类待裁而不是 6——㉑ 那一格写的是「(a) 已裁已落｜(b) 仍待裁」两态同行，表里按 ㉑ 先例**整行计入待裁**，按前缀切就把它的 (a) 脸认成了主态。这正是 FR-2 要写成「与文档自陈的数对齐」而不是「自己发明一套分类」的原因。
- **单源声明可解析**：形如「X 的单源在 Y 节」的句子，必须能**真的**从 Y 取到 X 的值。取不到 = 假单源。这是 FR-3 的对象。
- **单调不降**（MT4 的正确形态）：验证覆盖比 = 有机器证据的 FR 数 ÷ FR 总数。分母会随新 spec 增长，所以比值**会自然下降**；闸条件不是「≥ 某阈值」而是「**本轮不比上一轮低**，且降低时点名是哪几支 FR 造成的」。把 MT4 写成绝对阈值会造成「少写 spec 就能变绿」的反向激励。

## 4. 功能需求（FR）

### FR-1 DEV 编号连续且唯一

- FR-1.1 `^## [DEV-NNNN]` 的号段**无断号、无重号**——但「同号 + 标题含『补记』」是本仓的合法形态（「日志不回改」要求更正另起一笔），除外规则见 FR-1.4。
- FR-1.2 取号口径写死：最大号 + 1，且检查同时跑**工作树与提交树**两遍（本轮实测教训：只看一棵树会把最大号算错）。
- FR-1.3 违规形态必须能报：造断号样本（删中间一条）⇒ 报 1 违规；造重号样本 ⇒ 报 1 违规。分析文 §7 · Phase 0 表 0-4 行的门禁判据就是「对 3 个变异样本各报 1 违规」。
- FR-1.4 **本 FR 此刻就是红的——闸上线前要看的是「哪几号」，不是「几个数」**。本节登记时先写过一版字面计数（「工作树 96 标题／87 唯一号」），`DEV-0089` 一落笔它就变成 97／88——**自己采样自己烂**，正是 dev-plan §16.12 第 10 行的失效形态。所以这里只留**具名号集**与例外规则，任何总数一律现跑：
  `grep -oE '^## \[DEV-[0-9]{4}\]' DEV_LOG.md | sort | uniq -d`（工作树同号）· 同一条换 `git show HEAD:DEV_LOG.md |` 前缀（提交树同号）· 缺号 = 把**第一条 grep** 的输出（即去掉末尾 `| sort | uniq -d`）喂 `grep -oE '[0-9]{4}' | sort -u`，再与「0001 到最大号」的完整号段做差。
  - **提交树**：同号集只有 `{0085}`，且该号三支全是「主条＋补记＋补记二」⇒ **零真撞号**；缺号具名 0062、0063、0064、0066–0070、0072、0073、0080、0083、0086。
  - **工作树**：除 `{0085}` 这个补记组外，真撞号具名为 **0044、0045、0046、0074、0075、0076、0077**——每号各有**一支已入库 + 一支未入库新笔**，两两讲的是完全不同的事（例：`DEV-0074` 入库那支是「M4 技巧库规格」，未入库那支是「问答框架」）。**判据是「复算出的真撞号集是否为这 7 号的子集」**：并行会话随时可能再撞出一号，号集扩大时在 DEV_LOG 记新账，不要把本行改写成新快照。
  - **算术自证（只作自查不作断言）**：工作树比提交树多出的那批标题，应当**恰好**由两类构成——去填提交树上面那批缺号的笔，与撞在上面 7 号上的笔；两类的并集若覆盖不到多出的标题，说明数错了。填完剩 **0064** 无主，而它**不是新账**——`DEV_LOG.md` 的 `[DEV-0071]` 那一条已把它登记为「悬空编号」并写明真实号是 DEV-0066。⇒ 断号 0064 报**已登记**，不重复开账。
  - **闸的分工**：上面真撞号集里的每一号 ⇒ **error**（按 FR-5.1 同口径，历史不豁免）；「工作树里那批未入库的标题」不是违规，是并行会话的在制品，**只报数不判红**（否则每一轮都会被别人的 WIP 刷红，正是 §6.6 说的第二份债务）。
  - **对本笔的后果**：`DEV-0089` 按 FR-1.2 取号（取号当时两树最大号 + 1）此刻可用，但**上面真撞号集里每一组的成因都是「各自按自己采样时点的最大值取号」**，所以本笔的取号风险是实测过的、不是假想的——写完的自查是**不变量**不是计数：`grep -c '^## \[DEV-0089\]'` 在工作树应为 1、在提交树应为 0（入库后两处各转 1），命中数偏了就是撞号或重复追加（见 dev-plan §16.13 第 1 笔）。

### FR-11.2 否定断言的凭据不得指向空处

> ⚠️ **父 FR-11 的判据口径（措辞表、两档判定、凭据窗口三行）在 `docs/dev-plan-v0.2.1.md` 的 0-g 行** —— 本条只补「凭据落空」这一种失效形态，**不复制父条口径**（口径只留一处）。

- FR-11.2.1 **判红的口径（可证伪）**：否定断言的**凭据窗口**（父条定义：本行 ＋ 后两行）内，若凭据是一枚**自指指针**而它指向的位置在本文件里**不存在** ⇒ 判红。两种自指形态：**① 本文件 §N**（本文件无该节）；**② 本文件 FR-N[.M]**（本文件无该标识）。**为什么只判自指形态**：限定型节指针（`X.md §N`）落空**由 FR-12.1 判** —— 同一处再判一次就是两条口径管一件事；跨文件 FR 指针（`X.md FR-N.M`）**不判** —— FR 子编号常是节内有序列表条目而不是标识，实测全仓 **26** 处 `X.md FR-N.M` 指针的父 FR 都存在、只是子编号不作标识，判它必假红；裸 `§N` 不判（FR-12.2 已定）。
- FR-11.2.2 **两条排除（没有它们就是自指误报）**：① **凭据窗口里已有可复算命令 ⇒ 不判** —— 凭据已经成立，那条指针是订正段或旁证，不是凭据本身；② **指针在引号内（「」『』）⇒ 不判** —— 纠正段必须原样引出被纠正的那句话（父条的凭据窗口之所以是三行，就是为了容下这种订正段），引述不是活指针。
- FR-11.2.3 **判的是「凭据落空」，不是「断言为假」**：断言本身真假要真去跑一遍每条命令（那是 FR-8 的 MT6 面），本条只断「这条断言的复算入口指的东西不在」⇒ 它没有可复算落点。**本条是父 FR-11 之下新立的一条子项，不计入判据条数**（dev-plan §16.10：条数 > 8 即触发复审，现为 8）。

### FR-12 §-引用必须落在目标文件真实存在的节上

- FR-12.1 **只判「限定型」引用**（`文件.md §N`）：目标文件由**仓内实际文件名反查**得到（不靠正则猜文件名 —— 猜会过捕获，实测把两个文件名粘成一条）。
- FR-12.2 **裸 `§N` 只报数不判红**。理由有实证：裸引用在文档头部表格里常指**别的文档**的节 —— `§0.3`/`§0.4` 是跨文档的书写约定、`§10.4` 指 PRD 而非本文件 ⇒ 把裸引用当「同文件」判，实测会造出 **600 余条假红**。**假红比不红更坏**：刷屏的闸会被当噪音忽略。
- FR-12.3 **红的口径只有一个：可证伪的那一种** —— 被引编号的**顶层节在目标文件里不存在**（无歧义的死链）。父节在、子项没登记的（可能指未登记的表格行）⇒ **不判红**。**顶层节有两种写法，两种都算存在**：`## 2. 用户画像` 与 `## 第 2 章 · 现状量化`。只认前者会让 `docs/PRD.md` 与 `docs/analysis-2026-10-02-first-principles.md` 的 §2～§10 全成死链（实测），⇒ **少认一种就是假红**。
- FR-12.4 **子项形态收三种**：子标题（`### 3.2`）、节内条目（`- **6.2 …**` / 有序列表 `7.`）、表格行首标签（`| j | … |`，即「§7 的 j 行」）。少收一种就会把活引用误判成断链。
- FR-12.5 **已知存量走基线文件的精确登记**（不是通配）⇒ 本闸其余断链一律判红；登记项若不再出现，基线的反向检查会报「该清理了」。
- FR-12.6 **与既有面的边界**：本面只判「引用落不落空」，**不判被引内容对不对**（那是 FR-8 的 MT6 面）；也**不判裸引用的指向**（机器判不了，见 FR-12.2）。
- FR-12.7 **它有配套的三件**（不在本 FR 的判据面内，但缺了它本面就只能报数）：`scripts/section-ref-audit.ts --emit-rewrite-plan` 出**限定化改写清单**（只对「全仓唯一可解」的节号给建议，目标不唯一的列入待人工确认，**机器不猜**）；`--write` 出**对账表**（含「谁引用了 `docs/dev-plan.md` 的哪一节」＝拆分该文件前的影响面）；`--emit-alias-candidates` ＋ `docs/section-ref-aliases.json` 出**别名表**（见 FR-12.8）。
- FR-12.8 **裸引用的可判定化走「别名表」；它是建议层，不是判据层**。别名表有**两种**：

  | 表             | 键 → 值                    | 依据                                               | 落点                            |
  | -------------- | -------------------------- | -------------------------------------------------- | ------------------------------- |
  | **节号别名表** | 节号 → 来源文件            | 跨文件推断（人工逐节号裁定）                       | `docs/section-ref-aliases.json` |
  | **文档别名表** | 行内前缀（缩写）→ 来源文件 | **行内直接指称**（`m5 §7` 的 `m5` 就写在引用旁边） | `docs/doc-aliases.json`         |

  判定时**收窄**候选（登记的目标之外的文件不再是候选），**任一命中即绿**；**文档别名优先于节号别名**（前缀是同句上下文里的显式指称，节号别名是跨文件经验推断）。⚠️ **收窄前先验证目标**：目标文件**不含**该节号 ⇒ **不收窄**（退回机器自找）⇒ **别名写错只是静默失效**，既不会给出错误指向，更不会假红 —— 这比「写错就指向错文件」安全一个量级。**只登记指向集中到单一对象的键** —— 同一编号在不同上下文指不同对象的（如 `§7`、`§11`）**一律不登记**，单一登记会给错建议，比不登记更坏。

- FR-12.9 **别名表登记的「目标文件」必须还在仓内**（**唯一可证伪的一条**）：别名指向一份不存在的文档 ⇒ 它必然指错。⚠️ **只判这一条**：「目标存在但不含被引的节号」**不判**（FR-12.8 的「收窄前先验证」已让它静默失效，不产生错误指向）；「某个键当前没被任何裸引用用到」**不判**（前瞻性登记是正常的，不是失效）；「登记项多余」**只报数**。⇒ 这条判据**不会假红**：文件真的没了才会红。
- FR-12.10 **对账表是点时快照，必须能被发现过期**。⚠️ **只校验「拆分影响面」**（决策相关的那一节）：比对全文会对任何文档改动都报「过期」⇒ 天天红 ⇒ 等于没有这个检查。断链清单**不重复校验**（FR-12.1 已实时守住）。比对时**只比「节号 + 引用处数」**，**不比引用位置**（位置随任何编辑漂移，比位置会天天假红）。

## 6. 边界与异常

- **6.1 本闸只报不写**：任何 FR 都不得让 `docs:check` 修改文档内容。自动生成类（11-a 的「由脚本渲染回 md」）**不在本规格范围内**。
- **6.2 两树分歧是合法态但不是免检态**：工作树与提交树的计数可以不同（decisions.md ② 行就是这么自陈的），脚本必须**分别报两个数并都标口径**，不许只取一棵。
- **6.3 未入库文件的引用不可解**：**本行原把该判据挂在 FR-3.1 的解析路径下，2026-10-03 本笔已升为独立可判定的 FR-3.4**。PRD §10.0 第 1 条登记了这一族——指向未跟踪文件的链接在 GitHub 上是断链。挂在 FR-3.1 下的代价：那条路径要先解析自然语言句子，于是把一条一分钟就能机检的检查跟着 FR-3.3 的建议后置了。本行原样留着是为了留下「曾挂 FR-3.1」的痕迹（改判要能被别人推翻，就得看得见改前怎么写）。
- **6.4 按行计数的三类静默归零源**（本轮实测教训，必须写进实现约束）：`grep -c` 是按**行**计数，一行多处只算 1；`git show <path>` 在无该路径对象时返回空而不报错；BSD grep 的 `\s` 不匹配空白（macOS）。⇒ 每个计数类断言都要先做**正/负对照**。
- **6.5 表格列数校验必须先把 `\|` 摘掉再数**，否则把已正确转义的行判成违规（用户级电池的检查 8 就是这么实现的）。
- **6.6 闸自身的成本**（FP5／PRD §10.4.1 J6 推论）：本闸是给治理**减**工时的，如果它每轮产生 N 条无法就地处置的红，它就是第二份债务。⇒ 每次改闸规则都要在同一笔登记「本笔新增的违规条数」，让人看见闸的成本。
- **6.7 与用户级八道电池的「单源关系」待裁**：个人 skill 里那份脚本是本轮实际踩过全部八个坑的版本（含检查 8 的 python 表遍历、4a/4b 拆分、冻结面复数、`$CODE_EXCL` 排除产物）。`docs:check` 若另起一份实现，两处会漂。**处置见 §8.2 待裁②。**
- **6.8 排除产物**：判「某能力是否已实现」时先排除 `dist`／`node_modules`／`pkg`／`.vite`／`build`／`coverage`。本轮实测教训：电池检查 6 未排除产物时把 `@import` 判成「代码已存在」（6 个命中全是产物与 `index.css`），排除后为 1。
