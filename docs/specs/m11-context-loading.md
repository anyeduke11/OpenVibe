## 1. 目标与用户价值

- 用户组包时看到的是**一个包有多大**（字节、token 估算），看不到的是**「AI 到底读了多少」**。探针 A 实测：同一渲染链，规则数 8／32／128 时主文档分别是 **3,534／13,250／52,186 B**；换成索引臂恒 **≈336 B**；128 条时主文档单独 **≈20,498 tokens**（PRD §1.2 组 A，E0）。主文档随条数**线性膨胀**，而膨胀的那部分**未必被读到**。
- 分层加载要解决的不是「省字节」，而是**「让规则条数与主文档大小解耦」**——规则一多，包大到不能用、用户就不敢多写规则。
- **U10 已跑（2026-11-14）**，结论为**三档**（`docs/devlog-evidence/N1-probe/conclusions.md`）：
  - **claude-code：引用即生效**——主文档写 `@TERMS.md` 即自动 import（唯一「引用即生效」的平台）；
  - **cursor / codebuddy / trae：部分可行**——cursor/trae 可「按需读」（主文档写读指示，由规则驱动）；codebuddy 可把二级内容拆进 `.codebuddy/rules/` 模块文件（形态不同于主文件引用）；
  - **generic-agents / minicode：不可行**——维持 L0 全内联。
- **明确不做的一件事**：**不做「按需加载」这个交互概念**。本文件规定的是**协议**（谁读什么、读不到时怎么降级），不是给用户一个「加载/不加载」的开关。开关会把「哪些平台能降级」这件事变成用户的责任，而那是我们的责任。

## 4. 数据与核心概念

- **`LoadPlan`（一次注入的加载计划）**：回答「某平台这一次**必读**什么、**引用**什么」。形状是 `{ required: File[], referenced: File[] }` —— `required` 是主文档本身（必读，无它就什么都没有），`referenced` 是主文档里以指针形式指向、按需再取的文件。
- **三层**（PRD §4.3）：
  - **L0 必读主文档**：marker ＋ 标题 ＋ **一节索引**（每条引用只占一行：文件名、条数、为什么值得读）。
  - **L1 索引指向的已有二级文件**：`TERMS.md` / `CHECKLIST.md` / `SKILLS.md` / `PLAYBOOKS.md` —— **今天已经是这个形状**（§3-9），本文件不新造。
  - **L2 新增的规则与参考全文**：提议 `RULES.md` / `REFS.md` —— **今天内联在主文档里的那两块**（§3-1）。**本轮（N4）不落地 L2**，协议保留。
- **能力位（capability）**：每个 adapter 声明它**按引用再取的形态**。**四态**：
  - `'auto-import'`：主文档写 `@TERMS.md` 即自动 import（claude-code，唯一「引用即生效」）
  - `'on-demand'`：主文档写「按需读 TERMS.md」的指示，由规则驱动（cursor、trae）
  - `'module'`：二级内容以平台模块文件形态落盘、独立加载（codebuddy，`.codebuddy/rules/`）
  - `false`：无能力 ⇒ **维持 L0 全内联**（generic-agents、minicode）
  - ⚠️ **声明不了 / 未声明 ⇒ 与 `false` 同义**（K8 不变成回归的唯一办法）。
- **特性位（feature flag，manifest.l1）**：包级、**平台级开关**，控制各平台 L1 是否生效。形状 `Record<AdapterId, boolean>`，**只声明能力位非 `false` 的平台**。**默认值（manifest 未声明时）**：`claude-code=true，cursor=false，codebuddy=false，trae=false`（owner 2026-11-16 裁：**默认开 claude-code L1**，其余默认关）。生效规则：**平台 L1 生效 ⟺ `l1[platform]=true` 且 capability≠false**。
- **降级（degrade）**：能力位 `false` **或**特性位关 ⇒ **同一条内容保持今天的形态**。⇒ **降级的产物必须与今天逐字节相同**（E-6 硬约束）。
- **「未知」与「否」是同一件事**：U10 **已跑**，三档结论已定；**未纳入 U10 结论的平台一律按 `false` 处理**。这不是保守，是因为「声称能降级」而实际读不到，比「不降级」坏得多（用户会以为规则生效了）。

## 5. 功能需求

### FR-1 · 分层加载协议（三层，逐层定死）

1. L0 主文档的形态固定为：**marker ＋ 标题 ＋ 一节索引**。索引的每一行必须包含「文件名 ＋ 条数 ＋ 一句话为什么值得读」三要素 —— 缺任何一项即不合规。
2. L1 保持今天的样子（`TERMS.md` / `CHECKLIST.md` / `SKILLS.md` / `PLAYBOOKS.md`），**一字不改**。
3. L2 是**新增**的两个文件：`RULES.md`（规则全文）与 `REFS.md`（参考全文）。⚠️ **L2 本轮（N4）不落地**，文件名单沿用 PRD §4.3 提议，不自行改名。
4. L0 索引与 L2 文件之间是**单向引用**：L0 指向 L2，L2 **不指回** L0（避免循环引用与「读 L2 又要读 L0」的歧义）。
5. **每条规则/参考只允许出现在一个地方**：要么在 L2（被引用），要么在 L0（内联）。禁止两处都有（会造成「同一规则两个版本」）。**本轮 L2 未落地 ⇒ 规则/参考仍全文内联在 L0，不违反本条**。

### FR-2 · `LoadPlan` 的语义接口

1. 接口形状：`planMainFiles(pack, capability) → { required: File[], referenced: File[] }`。**能力位是入参** ⇒ 同一个包在不同能力位下产出不同的计划，这是特性不是缺陷。
2. **能力未知 ⇒ 必须退化为全内联**（PRD §4.2 的原文约束）。退化路径**不依赖任何错误处理** —— 是分支，不是 catch。
3. `required` **恒非空**且恒含主文档本身 ⇒ 「没有 required」是 bug，不是合法状态。
4. `referenced` 的顺序**确定**（码点序，与既有 `order-determinism.test.ts` 同口径）⇒ 同一包两次组装产出的 `files[]` 清单逐位相同。

### FR-3 · adapter 能力位（四态形态）

1. 能力位声明在 `packages/adapters/src`（能力位的唯一出处），形状是**四态**：`'auto-import'` / `'on-demand'` / `'module'` / `false`（**未声明与 `false` 同义**）。
2. **六平台三档**（U10 结论，2026-11-14）：

| 平台           | 能力位          | 依据（U10）                         |
| -------------- | --------------- | ----------------------------------- |
| claude-code    | `'auto-import'` | 唯一「引用即生效」（`@TERMS.md`）   |
| cursor         | `'on-demand'`   | 可写读指示、由规则驱动              |
| codebuddy      | `'module'`      | 可拆进 `.codebuddy/rules/` 模块文件 |
| trae           | `'on-demand'`   | 同 cursor 方向（待核真机）          |
| generic-agents | `false`         | 无引用再取能力                      |
| minicode       | `false`         | 无引用再取能力                      |

3. **不新增平台**：能力位挂在**既有六个** adapter 上，不新增第七个（E-5：`ADAPTER_IDS_P1` 的三个预留值 `windsurf`／`gemini`／`copilot` 仍只占位不实现）。
4. **能力位不改变任何既有 adapter 的默认行为** ⇒ 全部默认为 `false` ⇒ 今天的产物不变（这是 E-6 的前提）。**特性位才是生效开关**（FR-3.5）。
5. ⚠️ **能力位不得引入 core → adapters 的依赖**（E-1：`packages/core/src` 对 `@openvibe/adapters` 命中必须仍为 0）⇒ 能力位只能经**既有允许面**传入（`registry.ts` 的 `planMainFiles` 注入点），不得让 core 反向 import adapters。

### FR-3.5 · 特性位（manifest.l1）

1. `openvibe.pack.json` 新增 `l1` 字段：`l1?: Record<AdapterId, boolean>`，**只声明能力位非 `false` 的平台**；缺省 = 产品默认（`claude-code=true`，其余关）。
2. **默认值（owner 2026-11-16 裁）**：`claude-code=true`（默认开），`cursor=false`、`codebuddy=false`、`trae=false`（默认关）。**特性位关闭 ⇒ 该平台产物与今天逐字节相同**（与 E-6 同纪律）。
3. 特性位是**包级**配置（组包时可改），随包分发、随 sync 落盘；用户可逐平台开关（能力位非 `false` 的平台）。
4. 生效规则：**平台 L1 生效 ⟺ `l1[platform]=true` 且 capability≠false**。`false` 平台恒不生效（双保险）。

### FR-4 · L0 索引节（主文档术语表升级）

1. 主文档的**术语表节**（`PACK_SECTION_TERMS`）从今天的纯文本指针「见 `TERMS.md`（N 条）」升级为**一节索引**：每条二级文件一行，三要素齐全——**文件名 ＋ 条数 ＋ 一句话为什么值得读**。
2. 索引行格式（逐字定死）：`- \`TERMS.md\`：N 条术语——<一句话理由>`（码点序，同 `order-determinism` 口径）。
3. 术语表节的引用升级与 L1 引用形态配套（FR-4.5）：**L1 生效时**索引行按能力位形态渲染；**L1 未生效（特性位关/能力位 false）**时维持今天的纯文本指针「见 `TERMS.md`（N 条）」。
4. **不新造标记、不新增段**：索引节落在既有 `PACK_SECTION_TERMS` 段内，marker 与段常量不新增、不改名。
5. **`PLAYBOOKS.md` 的交叉引用行**（行为规则节内）同步升级：特性位开时为索引行（三要素），关时维持今天形态。

### FR-4.5 · L1 引用形态（按能力位）

**L1 生效（特性位开）时**，二级文件引用按能力位形态渲染：

| 能力位                         | 形态        | 渲染内容（主文档内）                                                                       |
| ------------------------------ | ----------- | ------------------------------------------------------------------------------------------ |
| `'auto-import'`（claude-code） | 自动 import | `@TERMS.md` 等 `@` 引用（平台自动加载）                                                    |
| `'on-demand'`（cursor、trae）  | 按需读指示  | 「按需读 `TERMS.md`」的指示语（由规则驱动）                                                |
| `'module'`（codebuddy）        | 模块拆分    | 主文档索引节指向模块文件；二级内容以模块文件落盘（`.codebuddy/rules/` 下，各文件独立加载） |

1. **`auto-import`**：主文档写 `@TERMS.md`（`@` 前缀引用）——平台自动 import，无需指示。
2. **`on-demand`**：主文档写「按需读 `TERMS.md`」的指示语——模型按规则驱动决定是否取。
3. **`module`**（codebuddy）：**二级内容以模块文件落盘**——`.codebuddy/rules/` 下产出模块文件（内容与对应二级文件一字不改，路径适配平台机制）；主文档索引节指向模块文件。
4. **L1 未生效**（特性位关/能力位 false）：**维持今天的纯文本指针**「见 `TERMS.md`（N 条）」——产物与今天逐字节相同。

### FR-5 · 单文件越阈告警（K1 的后半句）

1. `sizeEstimate` 增加**单文件**维度的告警：当**任一文件**的字节或 token 估算越阈 ⇒ 给出**指名**的告警（哪个文件、多大、阈值多少）。
2. **只提示不阻断**（与既有 `SIZE_WARN_THRESHOLD` 的处置一致：不阻断导出）。
3. 阈值**复用**既有常量，不新设第二个数字（避免两个阈值各说各话）。
4. 该告警**不参与**任何阻断判定，也不进 manifest（承 `context-density.md` FR-5.3 的既有钉法）。

### FR-6 · 扩展能力的保留（E-1…E-6 逐条可判）

1. **E-6（硬约束）**：能力位为 `false` **或**特性位关的 adapter，其产物与**今天逐字节相同** ⇒ 落为对照用例（`IT-L2-06`），**先红后绿**。
2. **E-1**：`packages/core/src` 对 `@openvibe/adapters` 命中 **0**（一条 grep 即可判）。
3. **E-2**：新增第 7 个主文件 ⇒ 既有六者 sha **集合逐一相等**（已有回归位可复用，见 §3-7）。
4. **E-3**：新路径是**纯追加**，指纹随之变（不是静默覆盖）。
5. **E-4**：未登记 id 被 `PackManifestSchema` 拒绝（`invalid_value`）—— 已有 schema 断言，补一条显式用例。
6. **E-5**：`ADAPTER_IDS_P1` 的三个预留值仍在。
7. ⚠️ **E-6 不成立则本 spec 不通过**（PRD §4.4 末句）：任何分层设计若使任一既有平台的产物无法降级回今天的样子，该设计不通过。

### FR-7 · A 级变更的流程要求（D-v25-1）

1. D-v25-1 已裁「做，等 U10 后生效」⇒ 走 A 级红线（PRD 第 8 章）：owner 裁定 → PRD 附录编号 → **`schemaVersion + 1`** → **先改 golden 再改实现**。
2. **特性位默认值按平台**（FR-3.5.2）⇒ 默认 claude-code 开、其余关 ⇒ 默认产物变化仅发生在 claude-code 平台，其余平台产物与今天一致。
3. ⚠️ **D-v25-1 与 D-v25-4 同批处理**（PRD 第 8 章 D-v25-4 行：「避免两次改字节」）⇒ 本 spec **不单独规定**反例指针的落点（那是 S5 的范围）。

### FR-8 · 不放松既有防线

1. 六个平台的**既有产物形态**（除 L0/L1 引用升级外）不变；`TERMS.md` / `CHECKLIST.md` / `SKILLS.md` / `PLAYBOOKS.md` 四份**一字不改**（内容不变；module 形态仅改落盘路径，见 FR-4.5.3）。
2. `pack-contract.ts` 的段常量与 marker **不新增、不改名**（L1 是**既有段内的引用形态升级**，不是新段）。
3. 空集合不产文件的纪律保持（§3-8）。
4. ⚠️ **不引第三方依赖**（PRD §4.2 末句：不引状态机库／ORM／事件溯源／向量检索）。

## 6. 边界与异常

### 6.1 索引行本身的格式

索引行是**协议的一部分**，不是自由文本。三要素缺一即判不合规 —— 理由：主文档是 AI 的入口，索引行缺了「为什么值得读」，模型就只会**机械跟随**而不会**按需取** ⇒ 分层就退化成「把内容搬走」，没解决问题。

### 6.2 能力位与「读不到」

能力位为真（非 `false`）但目标平台**实际读不到** L1（路径不对、权限不够、平台不跟随引用）⇒ 用户得到一个**缺内容的包**，且没有任何信号。
⇒ U10 已给三档结论；**未纳入 U10 结论的平台一律按 `false` 处理**（§4 末条）。

### 6.3 「收益未证 ⇒ 可能不做」是本 spec 的合法结论

PRD 第 10 章第一风险：「把能省字节当成有用」。U10 结论为**三档**（部分平台可行、部分不可行）⇒ 本轮按三档落地，**不做的平台维持 L0**，不假装问题已解决。

### 6.4 L2 为空集合

选了空的规则集 ⇒ 本轮不产 `RULES.md`（L2 未落地）；L0 索引里**也不得出现指向它的行**（否则主文档指向一个不存在的文件 ⇒ 比全内联更糟）。

### 6.5 降级路径必须与今天同形

能力位 `false` 或特性位关 ⇒ 维持今天形态。⚠️ 「内联」与「引用」两种形态的**主文档不能同时出现同一条规则**（FR-1.5）。

### 6.6 与 `context-density.md` 的分工

那份 spec 管**包总量与归因**；本文件管**单文件越阈**与**分层协议**。两者都碰 `sizeEstimate`，但**不共用一个字段**：本文件的单文件告警是**告警**（指名文件），那份的 `density` 是**读数**（分子÷分母）。⚠️ **不得**把单文件告警塞进 `density` 的结构里（会把「读数」变成「读数＋告警」的混合体）。

### 6.7 与 `m6-standard-pack.md` 的分工

那份 spec 是**包契约与 A 级变更流程**的总出处。本文件不另立流程，只引用（FR-7）。
