## 1. 第一性原理分析

### 1.1 功能本质

拆到不能再拆：

- 项目的**进展**在 OpenVibe 里今天是**人写的**：`dev_log_entries`（DEV/CHECK）、`tasks`、`project_check_states`。共同缺陷是**依赖人记得写**。
- 与此同时，用户在 AI 编程助手里**真实推进项目**的痕迹散落在三处：① 项目树里的规则文件（`CLAUDE.md` / `.cursor/rules` / `.trae/rules`）；② 代理工具的项目空间（`~/.claude/projects/*`、`~/.cursor/projects/*`）；③ 会话记录（jsonl / sqlite）。
- 这三处**已经存在**，只是没人把它们读回来与 `projects` 对齐。

⇒ **本质需求 = 把「已经存在但分散的 agent 工作痕迹」关联到「项目」这个实体上，使进展不再依赖人写。**

**不可替代的核心价值**（按不可替代度排序）：

| #   | 价值                     | 为什么不可替代                                                                                                      |
| --- | ------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| 1   | **进展不再依赖人写日志** | 人写日志的频率与质量不可控（仓内已有 `dev_log_entries` 但无强制）；机器痕迹是**被动产生**的，采集它比要求人写更可靠 |
| 2   | **跨工具的项目全景**     | 用户同时用多个代理工具（仓内已适配 6 个平台），任何单一工具的视图都是**残缺**的；聚合才完整                         |
| 3   | **可回溯的会话上下文**   | `contextService` 今天的 `logs` 段刻意不带 body（只给元数据）；会话原文是唯一能回答「当时为什么这么改」的材料        |

### 1.2 核心约束条件

| 约束                           | 出处                                                           | 对设计的后果                                                                                    |
| ------------------------------ | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **本地优先、不出网**           | 项目定位 ＋ owner 裁定                                         | 扫描器必须能在无服务端时运行；不得引入云同步                                                    |
| **路径权威必须复用既有闸**     | `inject/security.ts:41-67`                                     | 扫描根必须经 `resolveInside` 同类校验；不得新造一套路径规则                                     |
| **core 不得反向依赖 adapters** | E-1 边界（`packages/core/src` 对 `@openvibe/adapters` 命中 0） | 适配器只能挂在既有允许面（adapters 侧 ＋ server 注入），不得让 core 反向 import                 |
| **平台路径闭集不得破**         | `packages/adapters/src/adapters.test.ts:24-33`                 | 新增「读会话」能力是**新能力位**，不改写既有产物路径                                            |
| **空结果不产条目**             | [m11-context-loading.md](./m11-context-loading.md) §6.4        | 扫描无结果不得造假条目                                                                          |
| **单用户本机信任模型**         | F10（PRD v0.2.4:313-320）                                      | 持本地 token 的进程可读写一切；设计**不新增权限系统**，改为「显式开关 ＋ 明确告知 ＋ 一键清除」 |
| **不引第三方依赖**             | PRD v0.2.5 §4.2 末句                                           | 会话解析用 Node 内建能力（jsonl 逐行读；sqlite 经既有 `better-sqlite3`），不引新库              |
| **A 级冻结契约不碰**           | `SCHEMA_VERSION = 1`（`packages/shared/src/constants.ts:2`）   | 新增表/新增端点属 B 级；不动包契约                                                              |

### 1.3 底层实现逻辑：三条链路与「一次归一」

```
链路 A（路径扫描）   指定路径 → 复用 listSourceFiles 遍历 → 规则文件 → prompts 表（已存在）
链路 B（工具发现）   代理工具根（可配白名单）→ 发现器 registry → 项目空间清单 → 新表 agent_tool_projects
链路 C（会话采集）   项目空间 → 适配器 reader → 归一化 SessionRecord → agent_sessions（已存在）
                                                                           ＋ 新表 agent_session_messages
                                            ↓
                                     进展聚合器（纯读侧，不落新数据）
                                            ↓
                   ProjectDetailPage 新「进展总览」区 ＋ 设置页新「扫描与隐私」区
```

**关键取舍：一次归一（normalize once）。** 适配器**只负责把平台原生格式读成同一个 `SessionRecord` 形状**，不做任何语义推断；所有语义（进展、活跃时间、关联项目）由**读侧聚合器**从归一化数据算。⇒ 新增一个代理工具 = 新增一个 reader，不碰聚合逻辑。这是本设计可扩展性的唯一支点。

### 1.4 排除的表面经验性假设（逐条给反证）

| 经验性假设                   | 为什么错                                                                                                                                                                                                                                                                                            | 本设计的处置                                                                                       |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 「扫描越全越好」             | 全量扫描会把 `node_modules`、构建产物、`.git` 都读进来，既慢又污染；仓内已有 `SCAN_SKIP_DIRS`（`source-scan/files.ts:21-40`）与 20000 上限（`:43`）先例                                                                                                                                             | **白名单制 ＋ 跳过表 ＋ 硬上限**，三者缺一不可                                                     |
| 「会话原文进库后 AI 就能用」 | `contextService` 的 `logs` 段**刻意不带 body**（避免不可信输入出网，见 `contextService.ts:112-121`）；原文入库 ≠ 原文可出网。**实测凭据**：`grep -n 'body' packages/core/src/services/contextService.ts` ⇒ 该行只在「刻意排除」注释里出现，`logs` 段的构造（`:112-121`）不取 `dev_log_entries.body` | 原文**只进本地库**；出网仍走既有 `redactAbsolutePaths` ＋ 不带 body 的口径，**本设计不改这条红线** |
| 「实时推送才叫实时」         | 仓内无 SSE/WebSocket（全仓零命中；**实测凭据**：`grep -rn 'EventSource\|WebSocket' apps/server/src packages/core/src` ⇒ 0 命中）；「进展」是低频数据，30s 轮询足够；引入推送会新增常驻连接与断线重连语义                                                                                            | **轮询 ＋ 手动刷新 ＋ 扫描完成后立即 invalidate**，不引入推送                                      |
| 「扫得越勤越准」             | 会话文件在会话进行中持续追加，高频扫描会反复读同一批大文件；磁盘 IO 有成本                                                                                                                                                                                                                          | **按 mtime 增量 ＋ 用户可配频率（默认手动/每日）**，不做高频轮询                                   |

### 1.5 明确的非目标（Out）

- 不新增权限系统 / 多用户（F10 边界）。
- 不做云端同步、不做跨设备。
- 不做 AI 摘要入库 —— 聚合是**确定性**的（计数、时间、状态），不是推断。
- 不改写六平台既有产物路径与 `pack.lock` 契约。
- 不把会话原文接入 `contextService` 出网链路（红线不动）。

## 2. 两类扫描的边界定义

|                    | 链路 A：指定路径扫描                             | 链路 B/C：代理工具扫描                                                    |
| ------------------ | ------------------------------------------------ | ------------------------------------------------------------------------- |
| **输入**           | 用户显式指定的项目路径                           | 代理工具数据根（白名单内）                                                |
| **读什么**         | 项目树文件（规则 / 源码）                        | 项目空间目录 ＋ 会话记录                                                  |
| **写哪里**         | `prompts` 表（既有，`repos/prompts.ts:296-308`） | `agent_tool_projects` / `agent_sessions` / `agent_session_messages`（新） |

| **是否需授权**     | 不需要（用户主动指定）                           | 需要（设置页显式开启 ＋ 逐工具授权）                                      |

## 3. 功能需求（FR）

### FR-1 · 扫描路径白名单（链路 A 的前置）

1. 路径列表持久化于 `app_meta`（新键 `scanRoots`），**形制照既有 `skillScanRoots`**（`repos/appMeta.ts:78` → `routes/skills.ts:252-289`），不新造机制。
2. 每条路径保存前必须经 `resolveInside` 同类校验（`packages/core/src/inject/security.ts:41-67`）：不存在 / 非目录 / 越界 ⇒ 拒绝入库并给出可读原因。
3. **删除路径即停扫**，无需额外开关。
4. 路径条数上限 20；超出即拒（避免无界扩张）。

### FR-2 · 代码代理工具适配（链路 B/C 的适配器契约）

1. 适配器**只读**：输出 `SessionRecord`（§5.2），不写任何文件、不出网。
2. 适配器**不得假设平台 id 格式** —— `agent_sessions.external_session_id` 的注释明说「各平台形态未知，强校验必误拒」（`0007_local_events_and_agent_bridge.sql:37-38`）。
3. 工具清单是**注册表**（照 `packages/adapters/src/registry.ts:19-36` 形制）：新增工具 = 新增一个 reader，不改聚合器。
4. **未授权的工具零调用** —— 连目录探测都不做（判据见 §7 `BND-M12-02`）。
5. 每个工具有「测试连接」能力：只读一次目录，回报可发现的空间数，**不落库**。

### FR-3 · 数据采集范围（三级，默认最低）

1. **① 仅目录结构**：只写 `agent_tool_projects`，不读会话文件。**这是默认值。**
2. **② 会话元数据**：写 `agent_sessions`（时间、标题、消息数），**不读消息正文**。
3. **③ 含会话原文**：额外写 `agent_session_messages`。
4. 降级是**分支不是 catch**：范围低于所需时直接跳过该步，不报错、不重试。
5. 范围**只影响新数据**；已入库原文的清除走 §FR-5.3，不因范围调低而自动删。

### FR-4 · 项目空间与本地项目的关联

1. 关联键是**归一化路径**（`realpath` ＋ 去尾部斜杠），落 `agent_tool_projects.normalized_path`。
2. 匹配优先级：精确匹配 → 规范路径匹配 → **不匹配则不猜**，列入「未关联」区。
3. 一个本地项目可关联多个工具空间（同一目录被多个工具打开）。
4. `agent_sessions.project_id` 在**写入时**确定（该列已有 FK，`0007:41`）。
5. 关联错误可手工改绑 / 解绑（走既有端点扩展，不新增表）。

### FR-5 · 隐私与数据生命周期

1. **告知三句话必须出现在设置页**（F10 要求的写明边界）：
   - 所有数据只存在本机 SQLite，不上传任何服务端。
   - 会话原文以明文存在本机库中；任何能读取本机数据库的进程都能读到它。
   - 关闭「含会话原文」不会删除已入库原文，需显式「清除数据」。
2. 采集范围开关与逐工具开关是**双闸**：任一关闭即不采集。
3. **一键清除**只删三张新表（`agent_tool_projects` / `agent_sessions` / `agent_session_messages`），**不动** `dev_log_entries` / `tasks` / `prompts`；需二次确认。
4. 原文保留期限可配（`scanRetentionDays`），默认 90 天；超期清理只作用于 `agent_session_messages`。
5. 设置页必须显示数据存放位置（本地 DB 路径）。

### FR-6 · 进展聚合（读侧，不落新数据）

1. 聚合器是**纯函数/纯读**：输入归一化数据，输出展示模型；不写任何表。
2. 聚合内容：各阶段证据数、任务/日志时间线、会话活跃度（按日/周）、未关联条目。
3. **一致性提示只提示不阻断**（沿用仓内既有 warn 纪律）：当「阶段清单显示完成」但「近期无对应日志/会话」时给出提示。
4. 提示**不得**写成确定结论（不得出现「已完成」字样），只陈述证据缺口。

### FR-7 · 扫描调度与幂等

1. 单次扫描**可重入**：进行中重复触发 ⇒ 拒绝并返回「扫描进行中」。
2. 同一会话重复扫 ⇒ 按 `(session_id, seq)` UNIQUE 幂等；消息只增不覆写。
3. 增量判据用 **mtime + 文件大小**（不引内容哈希做增量，避免全量读）。
4. 自动调度是**条件能力**（T-7）：默认关闭，开启后频率可配（手动 / 每日 / 每小时）。

### FR-8 · 不放松既有防线

1. `packages/core/src` 对 `@openvibe/adapters` 命中仍为 **0**（E-1）。
2. 六平台既有产物路径逐字不变（`adapters.test.ts:24-33` 继续绿）。
3. 不改 `SCHEMA_VERSION`、`files[]` 清单、`targets` 枚举（A 级契约）。
4. 会话原文**不进** `contextService` 出网链路。
5. 不引第三方依赖。

## 4. 数据与接口

### 4.1 新增迁移：`packages/core/src/db/migrations/0024_agent_tool_scan.sql`

```sql
-- 代理工具项目空间（一次扫描的发现结果）
CREATE TABLE agent_tool_projects (
  id                TEXT PRIMARY KEY,
  project_id        TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  tool              TEXT NOT NULL,              -- claude-code|cursor|trae|...
  external_root     TEXT NOT NULL,              -- 工具侧项目根（绝对路径，仅本机展示用）
  normalized_path   TEXT NOT NULL,              -- realpath 归一后的本地路径（关联键）
  display_name      TEXT NOT NULL DEFAULT '',
  last_seen_at      TEXT NOT NULL,
  created_at        TEXT NOT NULL,
  UNIQUE (project_id, tool, normalized_path)
);

-- 会话消息原文（采集范围 = ③ 时才写）
CREATE TABLE agent_session_messages (
  id            TEXT PRIMARY KEY,
  session_id    TEXT NOT NULL REFERENCES agent_sessions(id) ON DELETE CASCADE,
  seq           INTEGER NOT NULL,               -- 会话内顺序
  role          TEXT NOT NULL,                  -- user|assistant|system|tool
  body          TEXT NOT NULL,                  -- 原文（可能含绝对路径）
  sent_at       TEXT,
  created_at    TEXT NOT NULL,
  UNIQUE (session_id, seq)
);

CREATE INDEX idx_agent_tool_projects_project ON agent_tool_projects(project_id);
CREATE INDEX idx_agent_sessions_project_started ON agent_sessions(project_id, started_at DESC);
```

⚠️ `agent_sessions` 表**已存在**（`0007:39-50`）且**全仓无写入路径**——本设计是它的**第一个写入方**。
**实测凭据**（「无写入路径」可复算）：`grep -rnE "(prepare\(|db\.)[^\n]*INSERT INTO agent_sessions" packages apps scripts` ⇒ 0 命中。⚠️ 若把命令放宽到 `grep -rn "INSERT INTO agent_sessions"` 会命中 2 处，二者都是**注释里的自述**（`packages/core/src/services/agentService.ts:272`、`apps/cli/src/commands/requirement.ts:131`），不是可执行语句 ⇒ 复算时必须用执行体形态，否则会把自述误读成写入点。

## 5. 异常处理

| 异常                        | 处置                                            | 可见性                             |
| --------------------------- | ----------------------------------------------- | ---------------------------------- |
| 扫描根不存在 / 无权限       | 跳过该根，记原因                                | 工作台失败条目 ＋ 设置页该路径标红 |
| 路径越界（含 symlink 逃逸） | 走 `resolveInside` 拒绝，记 `ESCAPE`            | 同上，**不静默**                   |
| 会话文件解析失败            | 跳过该文件，记原因；**不因单文件失败中止整轮**  | 失败条目                           |
| 单文件超上限                | 截断 ＋ 告警（沿用 `listSourceFiles` 既有行为） | 结果计数显示「已截断」             |
| 同一会话重复扫              | 按 `(session_id, seq)` UNIQUE 幂等              | 计数显示「新增 N / 跳过 M」        |
| 关联歧义（同路径多项目）    | 不自动猜；列入「未关联」区                      | 工作台提示                         |
| 扫描中重复触发              | 拒绝并返回「扫描进行中」                        | 按钮禁用 ＋ 状态端点               |
| 清除数据                    | 二次确认；只删三张新表                          | 设置页显式确认弹窗                 |

## 6. 交互流程

**首次启用**：设置页 → 添加扫描路径 → 逐工具授权 → 选采集范围（默认①）→「测试连接」确认可发现空间 → 工作台点「立即扫描」→ 查看结果 → 需要原文时再开③。

**日常使用**：工作台打开即见聚合视图 → 后台按频率增量扫描 → 有新会话时列表自动刷新 → 用户可对单条会话「改绑 / 解绑 / 忽略」。

**实时更新**：扫描完成 → `invalidateQueries(['agent-tool-projects' | 'agent-sessions', id])`；列表 `refetchInterval: 30_000`，扫描进行中缩短到 `5_000`。不引入推送。

### 7.1 未验证面（负向登记，不得读成已通过）

- **① 真实平台的目录结构未验**：Claude Code / Cursor / Trae 的实际数据布局**未在本机核验**；T-2 的 reader 实现必须先做真机目录勘察（只读），勘察结论落档后再写 reader。
- **② 会话文件格式未验**：jsonl / sqlite 的具体字段形态未核验；同上，先勘察后实现。
- **③ 「AI 会不会真的读原文」未验**：本设计只解决「把原文放到哪」，不解决「模型会不会用」——后者需 U10 类实验。
- **④ 大目录性能未验**：万级文件的扫描耗时与内存占用未测；硬上限（20000）只是兜底，不等于性能合格。
- **⑤ 保留期清理的触发点未验**：超期清理依赖调度；若调度关闭（默认），清理只在下次扫描时执行 —— 这是**已知延迟**，需在设置页写明。

## 8. 批次排期

**排序原则**：先做「不采集原文也能成立」的部分（风险最低、价值已可得），原文采集放在能力稳定之后；先做读侧聚合，后做写侧自动化。

| 批次    | 内容                                                                     | 依赖            | 回滚                               | 机器可判验收                                                   |
| ------- | ------------------------------------------------------------------------ | --------------- | ---------------------------------- | -------------------------------------------------------------- |
| **T-1** | 路径扫描增强：白名单 ＋ 跳过表 ＋ 硬上限 ＋ 失败可见性（**只读项目树**） | 无              | 关开关即退回 `scan --project` 现状 | 扫 201 个文件不静默截断；越界路径被拒且记原因；失败条目可见    |
| **T-2** | 工具发现：`agent_tool_projects` ＋ 发现器 registry ＋ 只读目录扫描       | T-1             | 清空表即回到「无工具视图」         | 夹具目录扫出预期空间数；symlink 逃逸被拒；未授权工具零调用     |
| **T-3** | 会话元数据（**不含原文**）：写 `agent_sessions`（该表首个写入方）        | T-2             | 清空表即回                         | 会话数/时间正确；重复扫幂等（新增 0 跳过 N）                   |
| **T-4** | 进展聚合与展示：时间线 ＋ 活跃度 ＋ 关联逻辑 ＋ 多源对照                 | T-3             | 隐藏卡片即回退（不改数据）         | 「阶段完成但无近期证据」提示可触发；未关联条目如实列出不为空   |
| **T-5** | 会话原文采集：`agent_session_messages` ＋ 范围开关 ＋ 保留期             | T-3             | 关开关 ＋ 一键清除                 | 范围<③ 时 `/messages` 结构性拒绝；清除后表空；超保留期自动清理 |
| **T-6** | 设置页「扫描与隐私」分区 ＋ 频率/触发配置                                | T-1…T-5         | 删分区即回                         | 五子区控件齐全；隐私三句话在页；配置写入 `app_meta` 可读回     |
| **T-7** | **（条件）** 自动扫描调度：mtime 增量 ＋ 频率配置落地                    | T-6；owner 授权 | 停调度即回手动                     | 变更文件被增量捕获；未变更不产生新扫描记录                     |

**顺序**：T-1 → T-2 → T-3 →（T-4 ‖ T-5）→ T-6 → T-7。

**编号归属**：属**新能力域**，不占 v0.2.4 的 R 批次与 v0.2.5 的 S 批次；在 `docs/tasks.md` 申请独立 T 号段（T14+），并在 `docs/decisions.md` 登记新决策号。

### 8.1 ⚠️ 三套 T 号互不通用（读前先对齐口径）

本仓现存**三套**含「T」的编号，语义各不相同，**引用时必须带前缀**：

| 编号形态    | 出处                          | 语义                         | 实例               |
| ----------- | ----------------------------- | ---------------------------- | ------------------ |
| **T1–T13**  | `docs/tasks.md` §2/§2b/§2c    | **任务组**（人日级，已排期） | T1 脚手架、T14 M12 |
| **T-1…T-7** | 本 spec §8                    | **M12 内部批次**（实现切片） | T-1 路径扫描增强   |
| **T0–T13**  | `docs/decisions.md` / DEV_LOG | **历史任务卡**（v0.1 时代）  | T10/T11 等         |

⚠️ **最易撞的是 `T-1` 与 `T1`**：前者是 M12 的第一个实现批次，后者是「工程脚手架」任务组——**两者毫无关系**。同理 `T-2` ≠ `T2`（M12 工具发现 vs 存储核心）、`T-7` ≠ `T7`（M12 调度 vs CLI）。

⇒ **书写约定**：M12 的批次号**一律带连字符**（`T-1`…`T-7`），任务组**一律不带**（`T1`…`T14`）。看到单个 `T` 后跟数字时，**先确认它出自哪份文件**，不要凭数字大小推断。
