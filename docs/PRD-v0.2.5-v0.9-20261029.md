## 第 0 章 · 一句话与三条目标

> **v0.2.4 修的是「注入与确认要么完整发生、要么完全没发生」；v0.2.5 修的是「知识进得去、阶段拦得住、旧了看得出来」——把一次性灌满改成按能力分层加载，把阶段文案改成有前置条件的闸，把知识回写补上时效判据。**

| 目标                      | 内容                                                                                                                  | 北极星（机器可判）                                                                  |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| **G1 必读量与知识量解耦** | 主文档不再随规则条数线性膨胀；规则/参考走「索引 + 二级文件」，且**按 adapter 能力可选降级**（未知能力的平台仍拿全文） | 规则数 8→128 时主文档字节增幅从 14.8 倍降到近常数；六平台既有产物字节在任一臂下不变 |
| **G2 交付环有闸**         | `spec_driven` 流程的「Spec 规格 → 实现」需可判前置（评审态、验收标准存在）；无前置不得推进，且拒绝必须显式            | 空清单直跳「实现」由「成功」变为可判定的拒绝；拒绝原因落在唯一一处状态机查表        |
| **G3 回写可判旧**         | 资产 ↔ 代码锚点面存在（或明确「不可判定」）；反例（负向约束）在抽取侧有来源；效能飞轮有可算下界                       | 「这条资产描述的代码变了」有确定回答（命中/未命中/**未知**三态，不折叠成「没变」）  |

**次序不可换**：G1 依赖 v0.2.4 R0（证据诚实）——索引化会把「没加载」变成「没加载」与「没这段内容」两种状态，先要有 `UNVERIFIED` 才谈得上分层。G2 依赖 G1 的产物结构（评审对象是规格文件，不是内联正文）。G3 是 G1/G2 的**维护机制**：没有判旧能力，分层与闸都会在半年内变成陈旧外壳。

## 第 3 章 · 第一性原理：整合后的最小闭环与瓶颈

### 3.1 把产品剥到不能剥

v0.2.4 §2.2 的三件事（注入、核验、人工确认）仍然成立，但它们只覆盖**最后一公里**。加上文章的双闭环后，完整链条是五段：

```
沉淀（资产库） → 编译（确定性 pack） → 注入（多 IDE） → 核验（diff/verify） → 回写（确认 + 判旧）
```

任何一段断，其余四段的产物都会腐坏：编译再确定，若规则全文灌进主文档，模型可用上下文就被挤光（G1）；注入再安全，若阶段可空跳，「按规格交付」就是文案（G2）；回写再顺滑，若无锚点，库里存的是**过去为真**的陈述（G3）。

### 3.2 瓶颈不是「能力不够」，是「信息经济学与节制缺失」

- **证据（E0，探针 A）**：128 条规则时，CLAUDE.md 单独 52,186 B ≈ 20,498 tokens，已超过 `SIZE_WARN_THRESHOLD = 12_000`（`packages/core/src/pack/size.ts:13`）；而告警目前挂在**聚合视图**（`apps/server/src/lib/pack-assemble.ts:112`），单文件越阈不报。
- **推导（不是直接测量）**：全包 313,278 B ≈ 6 × 52,186 ＋ manifest，即同一正文被复制 6 份。索引化后 ≈ 6 × 337 ＋ 52,186 ≈ 54,208 B ⇒ **落盘量降约 5.8 倍，必读量降约 155 倍**。省的主要是「每个平台每次会话都要读一遍」的那部分。
- **诚实边界**：这只证明「能省」，不证明「省了就有用」。真实收益取决于各 IDE 是否按需读二级文件（K8，未知）。

### 3.3 由第一性原理导出的四条不变量（续 v0.2.4 的 I1–I4）

| 编号   | 不变量                                                                                           | 违反时的现有表现                                  |
| ------ | ------------------------------------------------------------------------------------------------ | ------------------------------------------------- |
| **I5** | **必读量与知识量解耦**：主文档字节数不得随资产条数线性增长                                       | 探针 A：52,186 B / 128 条，线性                   |
| **I6** | **阶段推进必须有可判前置**：无证据不得宣称「已过评审」                                           | 探针 B：零勾选可直跳末段                          |
| **I7** | **知识的时效必须三态**（成立 / 已变 / 不可判定），不得把「无锚点」折叠成「没变」                 | 探针 E：schema 层根本没有锚点，任何「没变」都是猜 |
| **I8** | **扩展能力是回归对象，不是口头承诺**：加第 N 个 adapter 时，既有平台产物字节不变的断言必须可复跑 | 探针 F 已把该断言写成脚本，当前为真               |

I5–I7 是本版本的验收锚；I8 是**本文对「保留适配的扩展能力」这一要求的可判形式**（详见 §4.4）。

### 3.4 结构判断：缺的是模块，不是文件

## 第 4 章 · 目标框架（提议，未实现）

### 4.1 双环框架

```
        ┌──────────── 知识环（长周期） ────────────┐
        │ 资产库 → 编译(pack) → 分层加载(LoadPlan) │
        │      ↑                        ↓          │
        │   回写+判旧(FreshnessProbe) ← IDE 会话    │
        └───────────────────┬──────────────────────┘
                            │ 规格与阶段是两环的交接物
        ┌───────────────────┴──────────────────────┐
        │ 交付环（短周期）                          │
        │ 需求规格化(SpecRecord) → 评审闸(StageGate) │
        │   → 受控实现(tasks×spec 链接) → 验证联调   │
        │   → 知识回写（进入知识环）                │
        └──────────────────────────────────────────┘
```

关键结构变化：**分层加载不是渲染细节，而是一条协议**（谁读什么、读不到时怎么降级）；**阶段闸不是 UI 提示，而是一次状态机提交**（复用 v0.2.4 的 `CommitBoundary`，不另造事务框架）。

### 4.2 四个新深模块（建在 v0.2.4 的四模块之上）

| 模块                 | 唯一职责（一个问题的权威回答）            | 接口草案（语义，非实现）                                                                                  | 落在哪                                                | 依赖 v0.2.4        |
| -------------------- | ----------------------------------------- | --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- | ------------------ |
| **`LoadPlan`**       | 「这次注入，某平台必读什么、引用什么」    | `planMainFiles(pack, capability) → { required: File[], referenced: File[] }`；能力未知 ⇒ 必须退化为全内联 | `packages/adapters`（能力位）＋ `core/pack/composer`  | R0（未知态）       |
| **`StageGate`**      | 「从阶段 X 进 Y 是否被允许」              | `assertAdvance(project, from, to) → ok \| {reason}`；查表，禁止各 repo 自判                               | `core/repos/projects` 唯一入口                        | R1（同事务）       |
| **`SpecRecord`**     | 「这条需求的验收标准与评审态是什么」      | 正文＋验收条目＋`draft→reviewed→accepted` 状态机；**不改 `tasks`**，走关联表                              | 新 `core/spec` 仓储                                   | R1                 |
| **`FreshnessProbe`** | 「这条资产相对代码是 成立/已变/不可判定」 | `probe(assetId) → 'OK' \| 'DRIFT' \| 'UNDECIDABLE'`；无锚点必须返回 `UNDECIDABLE`，不得返回 OK            | 新 `core/freshness` ＋ `lang_topic_findings` 形状复用 | R0、R3（路径权威） |

**明确不引入**：状态机库、ORM、事件溯源框架、向量检索、新的 HTTP 端点数量爆炸（每模块至多一组端点）。

### 4.3 分层加载协议（S1 的产品语义）

- 三层：**L0 必读主文档**（marker＋标题＋一节索引）／**L1 索引指向的二级文件**（TERMS/CHECKLIST/SKILLS/PLAYBOOKS，已有）／**L2 新增的规则与参考全文**（`RULES.md`/`REFS.md`，提议）。
- 每个 adapter 必须声明它是否具备「按引用再取」的能力。声明不了 ⇒ **默认 false ⇒ 保持今天的全内联**。这条是 K8（未知）不变成回归的唯一办法。
- 兼容代价（诚实条款）：L2 化会改变**四根主文件的字节**、`files[]` 清单与指纹 ⇒ **A 级变更**，见 D-v25-1。

## 第 10 章 · 风险与诚实条款（本文可能在哪儿错）

- **最大风险：把「能省字节」当成「有用」。** 探针 A 只证膨胀曲线；真实收益取决于 U10/U11。若 U10 多数平台不读二级文件，S1 的正确结论是**不做**，而不是把指针去掉假装没问题。
- **第二风险：闸会催生绕过。** S2 若只做硬拒，用户可能直接改库或空勾选清单。本文不假设闸能替代判断，只要求「绕过是有痕迹的」（事件与 `check_states` 一致）。
- **第三风险：锚点是伪精确。** S4 的 `file_rel_path`+`line` 在重构后必然大面积失效（行号漂移）。若 U13 的「不可判定」占比过高，S4 应收缩为「文件级是否存在」而非行级。
