## 5. 需要 owner 裁的三件事（本轮我不就地改）

**Q1｜4 处「C 报成 B」（第 3 节 A1–A4）怎么补？** 这三档的差别是实质性的：v1.3② 影响 `clean` 删什么，v1.4④ 影响「一个没删也退 lock」，v1.5+`5a22800` 影响 `--json` 的必带键。
- **(a) 只改标签**：把四段的 §0.3 判级就地改为 B，升版号不动，链内加一行「2026-09-26 ⑥ 复核纠正」。代价最小，历史仍可追。
- **(b) 拆分升版**：把 A4 那笔「不另计次」的扩张补为 v1.5.1，正式走一次 B 级登记。更干净，但会动版本链这个单源。
- **(c) 连行为一起重审**：既然这四处现在才算第一次进 B 级复核面，逐条问「这条用户可见口径本身要不要保留」（例如 `hints` 必带、`--dry-run` 文案钉进契约）。**最贵，但这是唯一能让 owner 真正"签过"的路径。**

**Q2｜"版本链逐次 diff 不可复核"这条要不要立规矩？** 事实：m6b 的 v1.1–v1.3、m6a 的 v1.1–v1.2 都是**一笔写入**，git 里没有中间态，任何"按版本段读链"得到的判定都只是在读散文。
- 建议的规矩（要 owner 授权才写进 `dev-plan.md` §0.3 或 §13）：**升版段必须与 commit 一一对应；同一笔里补记多段升版时，须在链内明写"本段与 X 段同笔入库、无独立可复核态"**。今天这一笔做不到（历史已成形），只对**此后**生效。

**Q3｜第 3 节 B/C1–C4 这五条纯事实错报，属 C 级就地修吗？** 我的判断：是——它们不改任何行为，只把「登记了却没发生」「指错了节号」「区间腐烂」三处修回实况，与 `[DEV-0041]` 那轮 README/发布说明的定点修订同类。但 owner 曾定过「再出现有新行为后果的裁定仍须当场停下问」，这五条我判定**无新行为后果**，所以列出等一句"就地改"即可。
