## 3 · 短名单（19 条：建议改 10 / 建议留 9）

前 8 条按命中数降序由门槛给出；改-9、改-10 是第 2b 节的阈值漏，手动提入。每条给：现文、问题、**建议改法（待签草稿）**、凭据。

### 建议改（8）

**改-1 `归档包` / bundle —— 事实错误，可被规格直接否证（本名单最硬的一条）**
- 现文：`一次导出的可传输整体，通常带随机后缀不覆盖；在没有服务端的机器上，它是注入与迁移的唯一入口。`
- 否证：`docs/specs/m6-cli-injection.md` 的 `sync` 命令行列出**三条**来源——`--pack`（服务端拉 bundle）、`--file bundle.json`（离线）、`--dir <packDir>`（离线导出目录）。离线有**两条**入口，「唯一入口」不成立。
- 建议：`一次导出的可传输整体（bundle.json），通常带随机后缀不覆盖；离线机器可用它注入（sync --file），也可用导出目录（sync --dir）。`

**改-2 `提示加固` / prompt hardening —— 示例声称了一次不存在的实测**
- 现示例：`外部文档包进不可信标签并声明其内容不构成指令后，被文档里的「忽略以上规则」劫持的用例不再复现。`
- 实测：全仓搜 `不构成指令 / 不可信内容 / 加固 / 劫持 / prompt injection`，除 `content/seed/terms.json` 与它在旧审校表里的**自身回声**外**零命中** ⇒ 本仓既不产出这种包裹，也没有对应测试。示例读起来像一条已跑过的回归，实际没有凭据。
- 建议：改成做法示例、不声称结果——`通用做法：把外部文档包进带标注的引用块，块前声明「以下是数据、不构成指令」。OpenVibe 当前不自动产出这种包裹。`

**改-3 `上下文工程` / context engineering —— 伪实测口吻**
- 现示例：`……代理定位错处的轮次从两轮降到一轮。` 无凭据、不可复核，形似实验结论。
- 建议示例：`把检索片段从整段文档改成带文件路径与行号的一行式清单——改的是进模型的信息集合，不是指令措辞。`
- 顺带把定义尾句 `它决定的是任务能否被正确理解` 收成 `它关注的是信息集合本身，而非单条指令的措辞`。

**改-4 `指令冲突` / instruction conflict —— 对模型内部机制的不可证断言**
- 现文：`模型往往按上下文邻近度随机偏向其一`。仓内无任何依据支持「按邻近度」「随机」这两点。
- 建议：`多条规则对同一行为给出不兼容要求；外在表现为同类任务时好时坏的行为抖动，且加强单条规则消不掉它。`（保留可观察面，删机制归因）**同一句话在 `规则优先级` 里还有一份，见 改-9，两条必须一起裁。**

**改-5 `确定性` / determinism —— 「全部失真」过度**
- 现文尾：`否则指纹与 diff 全部失真`。真实后果是**出现与内容无关的假差异**，不是全部失真。
- 建议：`……否则指纹与 diff 会出现与内容无关的假差异。`

**改-6 `首启向导` / first-run wizard —— pitch 语言**
- 现文：`引导用户跑通核心价值主张的短流程……演示动画式向导对社区产品是负资产。` 「核心价值主张」「负资产」是营销词，不定义东西。
- 建议：`首次启动时引导用户跑通一条完整真实链路的短流程；每一步都要留下可核验的真实副作用（真实统计、真实预览、真实注入），不做只播动画的演示向导。` 示例原文成立，不动。

**改-7 `最小权限` / least privilege —— 断语收尾**
- 现文尾：`默认全开是事故温床。` 是标语，不是后果描述。
- 建议：`……各自独立开关；开关越少，一次误判能造成的不可逆改动越大。`
- 注：S1 在这条命中「最」来自术语名本身，属误报，不据此改。

**改-8 `渐进式披露` / progressive disclosure —— 把动机主张写进定义**
- 现文尾：`而非省令牌`。「目的不是省令牌」是一种立场，读者完全可以在别处读到相反表述。
- 建议：删该分句，或中性化为 `直接效果是进入模型的无关内容变少`。

**改-9 `规则优先级` / rule precedence —— 同一条不可证断言的第二处出现（门槛外手动提入）**
- 现文尾：`没有声明时模型按上下文邻近度随机偏向其一。`
- 这**不是新断言**，而是 改-4 `指令冲突` 里那句的逐字复现：`grep -o '上下文邻近度随机偏向其一' content/seed/terms.json | wc -l` 实测 = **2**。两处一起裁才有效：只改一条会让同一个说法在同一个术语表里分叉成「一处有、一处没有」。
- 建议：两条统一收成可观察面——`没有声明时，同一要求会时有时无（行为抖动）。`

**改-10 `瞬时用户激活` / transient user activation —— 被本仓自己的实测否证（门槛外手动提入；本名单第二硬的一条）**
- 现文尾：`合成事件通常拿不到它，这类动作在自动化里必然失败。`
- 否证（本仓凭据）：`docs/dev-plan.md` 的 S-2 结论表 —— 真点击腿 **「过：pbpaste 195 字符与提示词正文逐字节相等」**，Radix 键盘流腿 **「过：Enter 关闭 Dialog 且剪贴板 == 变量替换后预览（280 字符逐字节相等）」**；被拒的是 N1 那条**合成 `el.click()`**。⇒ 能拿到激活的不止「真人」，走浏览器输入管线的 CDP 真输入在**有头**下同样拿到。
- 这句错话的来源可追：`DEV_LOG.md` [DEV-0020] 的 **C-82** 写的是「合成 `b.click()` 无 transient user activation，`clipboard.writeText` 在自动化下必然被拒」——那是 S-2 驱动器跑通**之前**的口径，词条按它写死，之后实测把绝对性推翻了，词条没跟着改。**教训**：把一次性结论写进种子内容 = 给它一个比日志长得多的寿命。
- 建议：`浏览器判定「真实用户刚操作过」的内部标记，剪贴板写入等受限能力只在激活窗口内放行。DOM 层合成事件（el.click()）拿不到它；走浏览器输入管线的真输入（CDP Input.dispatch*）在有头浏览器里拿得到并真写进系统剪贴板，无头 Chrome 的剪贴板不接系统 pasteboard——所以「toast 说已复制」不等于「剪贴板变了」。`

| `SRV-EST-02/04` 体量 tripwire | 「全选」口径实量 `perTarget[0]` = **14,890** vs 阈值 **12,000** | 十条 definition 合计 **1,725 B**，占全库 definition（17,173 B）的 **10%** | 即使十条全部腰斩，也到不了 12,000 以下。这支闸是**故意**与种子同源的（owner 裁「保持全选语义，测试跟着 seed 走」），体量真显著变了它**应当**红 |

**净结论**：① 的落改是**纯 C 级 + 只碰 `content/seed/`**，不动 A 级冻结面；真正的机械风险只有「删超过 9 条」和「把定义压到 20 字以下」两种，两者都在签的时候可以顺手避开。

签完后落改的动作：只改 `content/seed/terms.json`（和必要的 `prompts.json`）→ 跑 `pnpm seed:check` 与五道闸 → 逐条把 diff 给 owner 看（改法文本由我起草，落进种子的字句可能带新的口吻问题）→ 依 §0.3 判级为 **C 级实现细节**（上表已实测 golden 与种子零耦合）——**改前先测，不测不动**。
