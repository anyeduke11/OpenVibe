# W-3 五人走查 · 执行手册与记录模板（2026-11-21 预制包）

> **定位**: 裁定点⑤ 选「圈定 5 人」后**零准备即刻执行**的预制品。判据单源 = 分析文 §10-1（挂 D28）：走查若证伪「阶段模型对真实用户有意义」⇒ **撤回 CP1/CP2/CP6，只留 CP3+CP5**。本手册把触发条件操作化成**预注册的打分规则**（跑完不许改——改了就是把判定做成想赢的样子）。
> **对象**: 走查对象是**阶段模型的设计**（CP1/CP2/CP6 未实现——growth-path v0.9 自陈「只是设计图」），不是已实现的 UI。给参与者看的是阶段定义与各阶段界面差异的**示意描述**。

## 1. 参与者与材料

- **5 人**：dogfooding 用户优先；没有 5 个真实用户时，5 人中最多 2 名项目内成员（成员的误读信号单独标注，不计入触发判定——他们对设计有知识增益，走查要测的是**没有知识增益的人**怎么读）。
- 每人 30–40 分钟；远程（屏幕共享）或本地；**逐字记录回答**（模板见 §4）。
- 材料 = 本手册 §2 的三张展示卡（读给参与者或屏幕共享）＋ 预注册打分表（§3）。

## 2. 三张展示卡（内容逐字来自 growth-path.md §FR 与 D28 五硬约束）

**卡 A · 阶段模型**：

> 你的 OpenVibe 有四个成长阶段：F0 跟随（刚装好，跟着开箱向导走）→ F1 实践（在真实项目里注入过包、勾过清单）→ F2 作者（导出过自己的包、写过自己的资产）→ F3 定标（你的包被 ≥3 个项目使用）。你的阶段由你的真实使用记录判定，不是你选的。

**卡 B · 阶段切换会变什么**（逐字强调这是全部差异）：

> 阶段只改三件事：**默认排序**（如 F0 把入门术语排前）、**表单预填**（如 F2 新建提示词时预填上次的结构）、**折叠默认值**（F0 收起高级块，一键展开）。**任何数据、任何报错、任何漂移与冲突，任何阶段都完整可见**——阶段永远不会隐藏功能，每个阶段都有「一键越级」看到全部。
> （这一条是 D28 硬约束 ①②④⑤ 的直译：永不隐藏数据/错误、阶段可见可解释、一键越级、升级不打断。）

**卡 C · 毕业信号**：

> F1 的信号：真实项目里注入过 ≥1 次且勾过 1 个阶段的清单。F2：导出过 1 个自己的包或写过自己的资产。F3：你的包被 ≥3 个不同项目注入。（阈值无数据支撑，走查任务 C 就在问这个。）

## 3. 预注册打分规则（跑完不许改）

**每名参与者 0–2 分的「阉割误读」分**：

- **+1**：任务 A（「你觉得从 F0 升到 F2，你的界面少了什么？」）的回答出现**「少／没了／被拿掉／被藏起来」类表述**，且**未自发提到**「可以调回来／一键越级／我自己能开」。
- **再 +1**：任务 B（演示一键越级后重问同题）**仍坚持**「少了东西」。

**判定（预注册，三档）**：

| 误读人数   | 判定                                                                              |
| ---------- | --------------------------------------------------------------------------------- |
| **≥3 / 5** | **§10-1 触发** → 撤回 CP1/CP2/CP6，growth-path 只留 CP3+CP5（D28 出口，原样执行） |
| 1–2 / 5    | 不触发；但 CP6 的阶段切换文案按误读点**改写**（登记进 growth-path v1.0 的变更）   |
| 0 / 5      | 通过，growth-path 升 v1.0                                                         |

**红线独立表**（与撤回判定并行）：任何参与者观察到「某信息在阶段切换后看不到了」⇒ 单独登记——D28 硬约束违规是**文案修正**（不撤回），但一例也不能留。
