## Q5 结论详述（2026-10-17 · agent 代查）

README §3.5 问三问，逐一作答：

### 问 1：MiniMax Code 就是 design.md 说的那个「MiniCode」吗？→ **不是**

证据链四条，每条都可复算：

1. **原始核验记录指向第三方项目**。`DEV_LOG.md:93`（DEV-0004 核验结论）逐字记着：
   「MiniCode ＝ GitHub 开源轻量终端 Agent（**LiuMengxuan04/MiniCode**，1.1k★ MIT），`/init` 生成 `MINI.md` → **升为专用 adapter**（D9）」。
   `docs/design.md:281` 那句「GitHub README 实证（`/init` scaffold `.mini-code/` + `MINI.md`；1.1k★ MIT）」就是这条的转写。
2. **更早一轮的记录说的是「检索无果」**。`DEV_LOG.md:69`（DEV-0003）原话：「MiniCode 检索无果诚实标注『待核验』并挂 T1」——
   即这个平台契约从第一天起就**没有官方文档可依**，是拿一个社区项目的 README 当契约。
3. **外部检索复核：MiniCode 是撞名，且与 MiniMax 无关**。检索「MiniCode + `MINI.md` + `.mini-code`」返回的前四个同名项目分别是
   `liumengxuan04/minicode`（轻量终端编码助手，多语言实现，定位「学习与实验、不建议直接用于生产」）、`NavishaShetty/mini-code-agent`、
   `naka1205/MiniCode`（事件驱动多提供商）、`Alcray/MiniCode`（Python，agentic runtime）——
   **四个都无 MiniMax 关联**，且其 README 均未出现 `.mini-code/` 或 `MINI.md` 这套约定。
   与第 1 条对上的是 `liumengxuan04/minicode`。
4. **本机实测：MiniMax Code 侧没有任何 MiniCode 约定的产物**。`~/.mini-code` 不存在；`~/.minimax` 下两层无任何 `MINI.md`；
   仓根无 `MINI.md`。而 MiniMax Code 的 dataDir 是 `~/.minimax/`（`skills`／`agents`／`plugins`／`mcp`／`sessions` …），
   与 `.mini-code/` 是两套无关的目录约定。

**结论**：`minicode` 这个 adapter id 里的「mini code」指的是 `LiuMengxuan04/MiniCode`，**不是 MiniMax Code**。

### 问 2：那 `MINI.md` 该投给哪个产品？→ **维持现状，投给 `LiuMengxuan04/MiniCode`**

adapter 当前已经瞄对了目标，**不需要改**。问 1 答「不是」并不意味着 adapter 错了 —— 它问的是「minicode 指的是哪个产品」，答案就是这个第三方项目。

### 问 3：那 `design.md` 里的「MiniCode」要不要改名为「MiniMax Code」？→ **不要改名，但建议加防混注记**

问 1 答「不是」，所以**不存在改名问题**，也就不用动 `design.md` §8 这个冻结面。

⚠️ 但本轮查出一处**真实的登记缺口**（不是改名问题，是「该登的没登」）：

- **MiniMax Code 读的是 `AGENTS.md`**，不是 `MINI.md`。证据：本机内置 `init` skill（`~/.minimax/.builtin-skills/init/SKILL.md:3`）明写产物是
  仓库根 `AGENTS.md`（agents.md 开放标准），全篇无 `MINI.md`、无 `.mini-code/`。
- 按 `design.md` §8 的分层口径（「有专有文件契约 → 专用 adapter；读既有产物 → 兼容矩阵，零代码」），MiniMax Code 应落在**兼容矩阵**那一栏。
- 实测 `git grep -i 'minimax|mcode|mavis' -- docs/design.md` → **0 命中**。§8 的兼容矩阵表里**没有 MiniMax Code 这一行**。

⇒ 即：本项目作者日常在用的这个客户端，其规则文件覆盖在设计文档里**无处登记**。谁若把 adapter id `minicode` 想成「我们自己在用的 MCode」，
会误判打包预览页的平台覆盖数（README.md:37 与 :124 两处都把 `MINI.md` 标为「MiniCode」，同样没有消歧）。

**该做什么**：在 `design.md` §8 兼容矩阵加一行「MiniMax Code → `AGENTS.md`」，并在 `minicode` 那行加一句「⚠️ 非 MiniMax Code，见 D9」。
**这是冻结面改动，需 owner 单独裁**，本会话不执行 —— 但缺口是真的，记在这里免得下一轮又以为「设计文档已经覆盖了 MCode」。
