## 版本 A · 资产口径（选中语义）

**语义**：分母 = 组包时**被选中的资产条数**——用户策展的心智单位。「密度高」的直接含义是「我选的每条资产平均摊多少 token」，与「去资产库少选几条」这条用户动作直接对应。

**落进 FR-2.2 的定义文本**：

> `denominator` = 本次组包**选中的资产条数**（按类型计数：prompts/terms/skills/flows 各自求和后相加；流程模板整条计 1，不按阶段拆分）。**资产是用户策展的心智单位**——分母的减法动作（去库里少选）与用户的可行动作一一对应。

**随批改动**：golden 期望值 **G1 → 519/8、G2 → 176/1、G3 → 698/9 保持不变**（现行期望值就是按资产口径写的）；§3-6 现算行回填「两读法差 28.2%，④ 裁资产口径」。

**已知代价**：同一条资产在产物里可能渲染成多个块（一个流程模板 → 3 个阶段块），按资产口径这些块的 token 被合并计入单条——「AI 实际按块读」的视角下密度被**摊薄**。

## 版本 B · 渲染段口径（展开语义）

**语义**：分母 = 主文档里**实际渲染出的段数**——AI 阅读的真实分块单位。「密度高」的直接含义是「AI 按块读的每一块平均摊多少 token」，与归因视图（FR-3 的 Top 榜）天然同构。

**落进 FR-2.2 的定义文本**：

> `denominator` = 主文档的**渲染段数**（按产物里的结构块计数：`####` 提示词块、`###` 阶段块、术语行、Skill 行各自求和）。**渲染段是 AI 阅读的分块单位**——密度与 FR-3 归因榜的粒度一致，「哪条占多少」在两个视图里指向同一个对象。

**随批改动**：golden 期望值**按 FR-2.4 的既有条款重写一次**：G1 → 519/**10**、G2 → 176/**2**、G3 → 698/**11**（渲染段数按 §3-6 口径现场重算后回填）；§3-6 现算行回填「两读法差 28.2%，④ 裁渲染段口径」。

**已知代价**：渲染段数随产物结构浮动（同一资产因阶段数不同贡献不同段数），「每条资产摊多少」的直觉读法不再成立——OM1 的界面文案必须把「每段」说清楚，否则口径腐化（§3-2 的教训）。

## 裁决辅助（一句话版）

- 关心**「我策展的东西摊多少」**→ 选 **A 资产口径**（golden 不用改）。
- 关心**「AI 按块读的每块摊多少」**→ 选 **B 渲染段口径**（与归因榜同构，golden 重写一次）。
