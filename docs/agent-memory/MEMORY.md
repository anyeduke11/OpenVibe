## 判据与闸（gate-design）— 判据的价值不在「写了」，在「违规时会不会有人知道」

| 条目 | 要点 |
|---|---|
| 判据正文写了断言却没写可执行检查＝闸是摆设 | 变异腿自己没红时**先怀疑闸没覆盖**，再怀疑变异没打中（「变异写错了」是更舒服的解释） |
| 判据的强度取决于 fixture 的体量 | 阈值型判据的 fixture 必须**大于**阈值；还要先证明「不裁剪时确实超预算」，否则断言可能是永真 |
| 逃逸口必须配一条「不注入时真跑」的守卫 | 只写注入用例 ⇒ **默认路径**上的缺陷结构上不可见；解析外部命令输出先剥 ANSI 转义码 |
| 摘要的「总数对」不等于「拆分对」 | 分解式必须有**规范出处**；判据要断成员集合相等，不是比计数 |
| 规格的示例值 ≠ 落库值 | 示例值是示意、判据才是约束；输出给人粘贴的地方，格式闸放在「生成输出」这一步 |
| 「加元素 ⇒ 不再是子集」是错的 | 集合关系要**实测 A\B 与 B\A 两个方向**；文档里的「订正」段落本身也要被复算 |

## 规格与文档（spec-doc-discipline）— 引用、数字、命令三样都要能复算

| 条目 | 要点 |
|---|---|
| 引用「既有 X」前必须实测它存在 | 三次假引用的教训；锚点写成 `文件:行号`，计数类断言要写扫描根与深度 |
| 假引用第五形态：文件系统态冒充版本库态 | 「磁盘上有」≠「版本库里有」；用 `git ls-files`，别用 `ls-tree HEAD` |
| 判「查无」需要多路径确认 | 单一检索面只能写「**在该处**查无」；跨文档的过时断言要回头改引用方 |
| 文档里写复算命令要防「自指」 | 命令会扫到它自己那一行；注释里也别复写那个裸串 |
| 在注释里「解释这个坑」会当场再踩一遍 | 别把会被解释器吃掉的字符序列原样写出来；改完**立刻重跑**，别靠肉眼 |
| 按锚点词 find 规格那一行几乎必然取错行 | **版本行会复述全文**；条件要加上被检对象自己的标识符 ＋ 配一支诱饵变异腿 |
| 逐字照抄源数据时「语义前缀」是数据的一部分 | 产出/练习/跳过是三种相反语义，剥掉就把「本段不学」变成「本段产出」 |
| 文档里的「实测数字」必须与实跑绑定 | 文档写的与实跑的要有闸绑在一起，且**断两个方向**；行内取数要锚在「订正后／实测」这类标记上 |
| 随时间派生的量必须自带参照日 | 闸按块自报的参照日算，不按跑闸那天；验收要两头都验（只挪参照日仍须红） |

## 工作树与提交（git-worktree-discipline）— git 的路径级操作不区分意图

| 条目 | 要点 |
|---|---|
| 并行会话共用一个工作树 ⇒ 白名单 stage | 禁 `git add -A`；提交后核对剩余脏项**逐字等于**已知清单 |
| 「M 文件」不等于「我改的」 | 归属看 **diff 内容**不看文件名；混了的文件宁可不提交，并在报告里点名归属 |
| 变异腿还原禁用 `git checkout --` | 用备份文件；「基线回到 N 绿」是**该腿的退出条件**，不是可选项 |
| 编辑长表格行时 old_string 须是完整整行 | 尾部会被**静默吃掉**且不报错；改完跑结构体检（逐行数竖线 / 比对表头列数） |
| Working tree 在我看不到时被 commit | commit 前先 `git log --oneline -5` 看是否有新 commit |
| Worker 越权自 commit | brief 末尾必须显式写 `❌ 不要 commit`；「worker 报告完成」≠「worker 没提交」 |

## 工具与环境（tooling-boundaries）— 工具的失败形态常与成功形态长得一样

| 条目 | 要点 |
|---|---|
| URL / 随机 ID 必须原样 copy | 凭记忆重打 ⇒ 用户点进去是 404 |
| bash sandbox `spawn EBADF` ⇒ 全客户端重启 | session 重启、派 subagent、派 codex **全部试过无效**；别浪费轮次，直接报 blocker |
| 内置 Browser 输入派发不可靠 ⇒ 改走裸 CDP | 先加一行 `console.log`：有日志＝派发层问题，无日志＝查代码 |
| 截图要落盘进仓 ⇒ 内置 Browser 给不了文件 | 裸 CDP `captureScreenshot` ＋ base64 落盘；截 GitHub 渲染视图而非 raw |
| 跨平台实测「全绿」多半量错了对象 | 先问「哪一步是**被测对象自己**做的」；凡命令行能做，都测不出客户端差异 |
| 把状态机做成「可点的活代码」 | 只断最终值区分不了「没发生」与「发生了但没被记录」；要断中间状态 |

## 假红分类（fake-red-triage）— 先分类，不是修

| 条目 | 要点 |
|---|---|
| 全量回归机器过载 ⇒ 几十支假红 | 重任务**串行**（不与 build 并发）；`--maxWorkers=3`；worker RPC 超时＝环境型 |
| 外部工具链不在 PATH ⇒ 假红 | `export PATH` 带上 Go 与 Homebrew；`spawn X ENOENT` ⇒ **第一反应查 PATH，不是查代码** |
| 后台跑回归时并发编辑源文件 ⇒ 瞬时假红 | 回归与编辑**不并发**；扫描型守卫读到的是文件系统某一瞬间 |
| 相对 now 的窗口 ＋ 写死日期 ⇒ 到期变红 | 写入日期**跟随当天**；窗口边界另由绝对窗口判据负责 |
| `spawnSync` 起子进程 ⇒ 父进程的本地服务假死 | 子进程必须异步；断言前先看服务端**收到几条**（0 条＝父进程被冻） |
| 判失败归属要用 HEAD 基线 worktree | **先建基线再动手**；基线红＝不是我造成的，不等于不可修 |

## 表与静态守卫（sql-table-semantics）

| 条目 | 要点 |
|---|---|
| 带静态守卫的仓里写 SQL 字面量 | 注释里的反引号 SQL 会被当代码；复合主键表 `ORDER BY` 必红 ⇒ **排序放 JS**（改白名单属契约改动） |
| 复合主键表按单列查 ⇒ 静默串行 | 必须匹配**全部键列**；查前先问「这个实体有几行？我拿的是哪一行？」 |

## 界面形态（ui-craft）

| 条目 | 要点 |
|---|---|
| EmptyState 必有 3 态 | `empty` / `no-result` / `error`，各配各的 CTA；`error` 必须可重试 |
| `selectAllMode` 状态机反模式 | 用 discriminated union 表达选集；过滤条件变化强制回到 `none` |
| alert / confirm 全仓泛滥是反模式 | `sonner` toast ＋ 项目自有 Dialog；批量不可逆操作要 requireText 二次输入 |
