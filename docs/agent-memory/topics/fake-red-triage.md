# 假红分类：环境型红 vs 代码型红（合并 5 条旧条目）

Type: incident-lesson

**一句话**：全量回归出现几支红时，**第一反应是分类，不是修**。假红比不红更坏 —— 人会去「修」一个没坏的东西。

## 判定顺序（四步，缺一不可）

1. **看错误形态**：`AssertionError` ⇒ 才考虑代码型；`Test timed out` / `spawn X ENOENT` / worker RPC 超时 ⇒ 环境型。
2. **看耗时**：比基线高一个数量级 ⇒ 环境型（真实回归不会整体变慢 100 倍）。
3. **看 `uptime` 的 load average**：三个数都在 30+ ⇒ 环境型（本机常驻 Lark / usernoted / CodeBuddy 等进程）。
4. **不编辑任何文件**单独重跑 ⇒ 绿 ⇒ 判「环境型」。

⚠️ **三步都指向「绿」才下环境型的结论**；只跑一次就下结论会把真回归放过去。

## 五种已实测的假红形态

| 形态 | 错误形态 | 根因 | 处置 |
|---|---|---|---|
| **机器过载** | worker RPC `Timeout calling "onTaskUpdate"`；或大量 `Test timed out in 5000ms` | 全量 vitest 与 vite build **并发**；load average 50+ | 重任务**串行**；`--maxWorkers=3`；unit/web 两层默认 5s 闸抬到 20s（见 `vitest.config.ts`） |
| **外部工具链不在 PATH** | `spawn go ENOENT`；或断言形态自相矛盾（期望 parser 却得 heuristic） | Go 在 `/usr/local/go/bin`、Homebrew 在 `/opt/homebrew/bin`，**都不在**非交互 shell 的默认 PATH | 每条命令前 `export PATH="/usr/local/go/bin:/opt/homebrew/bin:$PATH"`（本仓 node 在 `/opt/homebrew/bin`） |
| **并发编辑的中间态** | 全仓扫描型守卫报命中（它读的是文件系统某一瞬间） | 后台跑回归时**同时**改了源文件 | 回归与编辑**不并发**；后台跑时只读仓内文件 |
| **日历漂移到期红** | 断言值变 `undefined`（窗口下界推走） | 生产侧用 `date('now', '-N days')`（按跑测那天算），测试把日期**写死** | 写入日期**跟随当天**；窗口边界另由**绝对窗口**判据负责 |
| **spawnSync 冻住父进程** | 子进程访问父进程里的本机服务永远超时（`statusCode=null`，服务端收到 0 条） | `spawnSync` 阻塞父进程事件循环 | 子进程必须**异步**（`spawn` + 监听 `close`）；断言前先看服务端收到几条 |

## 两个同源的一般化

- **缺外部工具会改变被测行为**，不只是让测试挂掉 ⇒ 断言会以「逻辑矛盾」的面貌出现 ⇒ 极易误判为「回退逻辑坏了」。
- **守卫读的是文件系统某一瞬间** ⇒ 那一瞬间可能正是你正在写的半成品。

**apply when**：任何「全量跑出很多红」的场合；尤其当红点横跨多个不相关的模块（⇒ 不像一处改动造成的）。

## 两种新形态（2026-10-24 实测）

| 形态 | 错误形态 | 根因 | 处置 |
|---|---|---|---|
| **判定基于工作树 ⇒ 他人未提交的回退会改变判据结论** | 闸报「引用指向已删的节」，而 HEAD 里那一节好好地在那儿 | owner 裁定「原样保留」一组**未提交**改动（内容实为对已落地文档的回退，删掉了一整节）⇒ 扫「引用目标是否存在」的闸读工作树 ⇒ 那节不存在 ⇒ 死链 | 报告**注明判定基于工作树**（不是 HEAD）；这类红归**他人成果面**只报数不判红；owner 裁定保留 ⇒ 后果要**显名上报**（「保留的决定会让 X 条指针断掉」） |
| **描述断指针的文字本身也会被扫成断链** | 闸在日志条目里报出一条「指向不存在节的引用」，而那行文字正是在**说**「这里有个断指针」 | 扫「引用形态」的闸扫的是**文本形态**，不是语义 ⇒ 引用死指针的**描述**与**真死指针**在文本上无差别 | 闸要能区分「活文档面」（判红）与「历史记录面」（只报数：日志、存档、复审记录记的是「当时为真」）；**只报数的那一面的数不能写死** —— 写它的文档本身会改变它 |

**一般化（第三条）**

- **闸的「红」必须落在可证伪的一种情形上**：其余形态一律降级为「不可判」。例：判「`X.md §N` 断了」时，唯一能证伪的是「目标文件连顶层节 N 都没有」；父节在、子项未登记 ⇒ 不可判（宁漏不可造假红）。
- **「不可判」不是失败，是设计**：把它**显式归桶并报数**，读者才知道边界在哪；静默忽略 ⇒ 读者会以为闸管到了。

**apply when（补充）**：闸要扫「引用/指针/链接」这类**文本形态**时；或 owner 裁定保留某组未提交改动时。
## 六、解析/索引层**漏掉一种合法写法** ⇒ 整类引用**批量**假红（不是零星假红）

假红不总是「一条规则配错了」。有一种形态是**解析层覆盖不全** ⇒ 某一类引用**成批**被误判。

本轮实例：仓内文档的顶层节有**两种**写法 —— `## 2. 用户画像` 与 `## 第 2 章 · 现状量化`。索引只认「数字开头」的那一种 ⇒ 索引里只有 `2.1`／`2.2` 而**没有 `2`** ⇒ 引用「§2」被判成「顶层节不存在」⇒ 断链。`docs/PRD.md` 与 `docs/analysis-…md` 的顶层节全是「第 N 章」写法 ⇒ 这两份文件的 §2～§10 **全是死链**。

- **识别特征**：假红**成批出现**且集中在**同一类写法**上 ⇒ 先怀疑解析/索引层的覆盖度，而不是规则本身。
- **手法**：拿一份**有代表性的真实文件**，把它的标题形态**列全**（`grep -E '^#+ '`），与索引实际认出的节号**逐条对照** —— 差集就是漏掉的写法。
- ⚠️ **漏掉的往往不是「另一种写法」，而是「另一种层级」**：顶层节有 `## 2. …` 与 `## 第 2 章 · …`，子节有 `### 2.1 …` 与 `- **2.1 …**` 与 `| j | … |`（表格行首标签）。**少认一种层级，整类引用全成断链。**
- **代价不对称**：多认一种写法最多让一条引用从「不可判」变「绿」；少认一种 ⇒ 一整类引用变「红」。⇒ 索引层应当**宁滥勿缺**（拿不准就当它存在，让它走「不可判」，别让它红）。

**apply when**：任何「按标题 / 按行首 / 按某种文本形态建索引」的检查器；判红**成批**出现时，先做「真实文件形态 vs 索引已认形态」的差集对照。

**同源提醒**：判据「在跑」与判据「**看得见它要管的东西**」是两件事 —— 本轮还有一条同族缺陷：审计函数**没把「已知存量」传进去** ⇒ 已登记的项照样每次进 findings ⇒ 基线的**反向检查**（登记项不再出现 ⇒ 报「该清理了」）对它**永久失效**。⇒ 接到反向检查机制上时，要确认那条机制**真的收到了被登记的对象**。
