# 判据与闸的设计纪律：怎么写一条「能真红」的判据

Type: pattern-anti

**一句话**：判据的价值不在「写了」，在「**违规时会不会有人知道**」。写不出可执行判定式的判据只是愿望，不该进验收条款。

## 一、闸必须能红

- **判据正文写了断言 ≠ 有检查**：我给一条判据写了完整断言描述（「`lang_topics` 没有 `phase_id` 列，且仓内不存在站↔段映射表」），自检脚本里却只检查「正文写没写明不做逐格映射」——那是检查**文字在不在**，不是检查**规则有没有被违反**。⇒ 变异腿（往表里加一列）没红。
- **我验证判据的方式错了**：判据真正要回答的是「违反了它之后会不会有人知道」；「这句话在文档里吗」永远绿，「违规会不会红」才可能是红。
- **反向判据（不得存在 X）最高危**：它天然没有正向痕迹 —— 加一列、多一张表，代码照常编译、测试照常过、文档读起来完全成立，只有专门那条检查会红，而人不会想到去写那条检查。
- **变异腿必须含「照着判据写一个违规样本」这一类腿**，不能只变异计数与文案。
- ⚠️ **变异腿自己没红有两种可能**：① 闸没覆盖 ② 变异没打中目标。**先怀疑闸**（①），因为「变异写错了」是更舒服的解释。
- **检查对象必须是被约束的那个实体**，不是描述它的那句话。

**apply when**：任何「禁止 / 不得 / 不许存在」型判据；任何刚写完的判据问一句「我能写出一个让它变红的样本吗，写不出就别收」。

## 二、fixture 体量必须大于被测阈值

写「阈值型」判据（预算裁剪、分页上限、体量上限、超时）时，fixture 体量若小于阈值，那条用例**结构上就永远测不到任何东西**。

实例：`{logs,assets,checklist}` 序列化 ≈ 183 字节，被测下界 `MIN_BUDGET_CHARS = 200` ⇒ 任何合法 budget（≥200）都压不动它。它当时是红的，但红的原因与判据无关；更危险的是日后只要有人把断言改松就变成**永真**。

处置两层：
1. 换用真实体量 fixture（6 条 · 长文案 ≈ 617 字节），让预算 220 真能逼出裁剪；
2. **在用例里先证明「不裁剪时确实超预算」** —— 把「fixture 被改小 ⇒ 用例失效」本身也变成可红的判据。

**为什么没有任何工具会提醒你**：类型检查不管、eslint 不管、`pnpm test` 绿。它只在跑变异腿时现形。

**变异腿的三种有效腿**：把被测分支改成永不触发（如 `if (false)`）；把 fixture 缩回小体量；把实现改回**注释声称的反方向**（本次 `shrinkLogs` 从数组末尾倒着走，而 `DevLogRepo.list()` 是 `created_at DESC` 最新在前 ⇒ 实际留的是**最旧的**，且不报错不留痕）。

**apply when**：任何 `budget` / `limit` / `pageSize` / `timeout` / 「超过 N 就 X」的判据用例；给已绿但「测不出东西」的用例做变异核验时，优先跑「缩 fixture」这条腿；「先到者不变」「顺序固定」「最新在前」这类**方向型**判据，必须有一条用例钉死排序方向。

## 三、逃逸口（可注入替身）必须配一条「不注入时真跑」的守卫

给实现留可注入替身（假 runner / 假 IO / 假时钟）是好做法，但**只写注入用例时，「默认路径」上的缺陷在结构上不可见** —— 那些用例永远不经过它。

实测：`scripts/mutation-run.ts` 的 `runLeg(leg, repoRoot, run = defaultRunner)` 有 21 支全用注入的用例，而 `defaultRunner` 里设 `CI=1` ⇒ 子进程 vitest **强制上色**，汇总行变成 `ESC[2m      Tests …`，而正则 `^\s*Tests` 要求行首是空白 ⇒ **每一条真跑变异腿都被误报成「测试崩了」**。注入的假输出是干净文本，永远看不到。

- **通用形态**：任何 `^\s*` / `^\d` / 行首锚定的解析，跑在**外部命令的输出**上时都要先剥 ANSI 转义码（`/\x1b\[[0-9;?]*[ -/]*[@-~]/g`）。`CI` / `FORCE_COLOR` / `TERM` 一变，同一份代码就换一种输出形态。
- **断言不要写死**「恰好 N 次调用」「恰好 3 个枚举值」，改成从真相来源派生（`COMMANDS.length`）；写死会在集合扩容时红，但红的原因会与别处回归混淆。
- **判据要断真实内容而非次数**（断第二次请求的 `command` 字段逐字为 `requirement`，而不是「发了两次」）。
- **验收**：默认路径必须有一条**真起子进程**的用例（可慢，但要显式 timeout 且归入独立跑法，别混进日常热路径）。

**配套提醒**：补这条守卫时可能发现某个桩需要「翻面」（桩里原先故意返 404 来钉「不许发埋点」，契约一扩就得改成正常登记）—— **守卫的方向本身也是契约的一部分**，扩契约时要一并翻面，否则钉的是旧契约。

## 四、总数对 ≠ 拆分对

速览页/摘要页最典型的病不是「数写错了」，而是**总数对、拆分错**。

实测：M9 spec §0 速览写「**十七张新表**（知识点 8 · 源码与记忆 3 · 资源 2 · 模式 3 ＋ 语言差异 1）」—— 8+3+2+3+1 = 17，**总数与正文一致**，而正文（§3.1）根本没有分组口径可对 ⇒ 那串分组是**凭空写出来的**。按真实的 17 张表逐张归组，正确分解是「知识点 7 · 源码与记忆 4 · 资源 2 · 模式与阶段 3 ＋ 语言差异 1」，**错位一格**。

- 摘要里凡出现「总数（分项 1 · 分项 2 …）」这种**分解式**，分项**必须**在正文某处有**规范出处**（一张分组表 / 一句定义 / 一个可解析的口径行），摘要只做**引用**。
- 判据要**分别断总数与分解**：总数对得上 ＋ 分解逐项对得上 ＋ 分解并集 == 正文全部对象（**不重不漏**）。
- 分解的成员集合要与正文对象集合做**集合相等**比较，不是比计数 —— 计数相等但成员错位，正是本例。

## 五、规格的示例值 ≠ 落库值

spec 里举例 `matched_pattern = 'ast.Call'`（解析器节点名），而判据要求 `grep -n '<matched_pattern>'` 必须命中它声称的 `file:line` ⇒ `'ast.Call'` 里的 `.` 在 BRE 里是「任意字符」，**grep 跑得动却命中不到那一行的字面内容**。⇒ 落库落「命中的那段源码文本」（`import logging`），规范模式名另存模式表供界面显示。

- **规格里的示例值（`如 'xxx'`）是示意，判据才是约束** ⇒ 两者冲突时按判据走，并把冲突**登记为「规格张力」**（写进 dev-plan 的「已产出」块），不要偷偷改规格，也不要把示例值照抄进数据里。
- **写入侧保证了格式，读侧还要再兜一道（纵深防御）**：库里可能有人工脏值 ⇒ 导出侧再兜一道。凡是「输出物给人粘进终端」的地方，格式闸放在「生成输出」这一步，不只放在「写进去」那一步。
- **守卫要自证**：先断言「脏值确实含危险字符」，否则「导出后没有危险字符」这条断言可能是**恒真**。

## 六、集合关系要实测两个方向

规格里写「补建了 N 条 ⇒ `A.required` 不再是 `B.required` 的子集」—— **这个推理方向反了**。往**被包含方**（B）加元素，**不会**破坏 `A ⊆ B`；只会让 `A ⊆ B` 从「相等」变成「真子集」。

实测：熟悉必学 72 ⊆ 精通必学 78（熟悉必学而精通不必学 = **0** 条），**⊆ 仍然成立** ⇒ 被那条错误表述推着做出来的「第三档不再是恒空分支」结论也是错的。⚠️ 后果不是文案瑕疵：它把一个**恒空分支**说成「可落地」，下一步就有人去实现那个**永远不会出现的状态**。

- 凡规格出现「加了 X ⇒ 集合关系 Y 变了」，**先实测两个方向**：`A \ B` 与 `B \ A` 各多少条，再决定结论。
- ⚠️ **「⊆ 被破坏」只有一个成因：往被包含方里加了不在包含方里的东西** —— 往包含方加，关系只会更紧（相等 → 真子集）。
- 文档里「订正」段落**本身也要被复算**：错误表述往往就是上一轮的「订正」引进来的 ⇒ **订正不是免检区**。
- 判据要断**两个方向**（`A\B` 与 `B\A`），只断「包含成立」的那一半 ⇒ 等号退化成子集时看不出来。

## 七、「零风险」可能是**漏报** ⇒ 必须单独断言「那一处看得见」

给一段代码加守卫时，最容易写出的结论是「这一处**零风险**，因为有闸守着」。**这句话本身就是要验的对象** —— 闸可能根本看不见那一处。

本轮实例：M9 增强 3 修的是「时间派生量守卫看不见 JS 侧的相对窗口」（`LocalEventsRepo.summary` 那个事故现场被漏掉）。修完之后很容易顺手写一句「`summary` 现在有闸守着了」。但**「修完它有闸」与「闸当场看得见它」是两件事** —— 前者是设计意图，后者要一次实跑。

**通法**：
- 判据写完，除了「违规会不会红」，还要补一条**「现场看得见」的正向腿**：用那个**具体的**事故输入（真实的表名、真实的调用形状）喂进去，断言闸**真的报了**，而不是「没报」；
- ⚠️ 这条正向腿的常见失败形态是**假阴性冒充通过**：闸没看见 ⇒ 什么都不报 ⇒ 「没红」被读成「安全」。⇒ 正向腿必须**断「报了」**，不能只断「没红」；
- 配套：**夹具的方法名不要与生产方法同名**（本轮把夹具的 `summary` 改名 `fixtureSummary`），否则守卫扫源码时会**扫到自己** ⇒ 自我命中掩盖真命中；
- 同源提醒：**「零风险」「没有 X」「全仓无 Y」这类否定式断言都要自带复算凭据**（本仓 FR-11 已是这条的机器形态）。

**apply when**：任何「加了守卫 ⇒ 这里就安全了」的收尾结论；任何以「没红」为通过标准的守卫（守卫必须有一条**断「报了」**的正向腿）。
