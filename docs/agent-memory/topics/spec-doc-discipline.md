# 规格与文档纪律：引用、数字、命令三样都要「能复算」

Type: pattern-anti

**一句话**：文档腐烂的三大来源是**假引用**、**过期数字**、**自指命令**。三者都能靠落笔时多花 30 秒避免。

## 一、引用「既有 X」前必须实测它存在

写 spec 时我三次造出**假引用** —— 引用的东西在仓库里不存在或形态完全不同：
1. 「沿用既有 `EmptyState` 纪律」⇒ `grep -rln 'EmptyState' apps/web/src --include='*.tsx'` → **0 命中**，组件根本不存在（照另一个项目的记忆写的）。
2. 「本仓信封无 409 先例」⇒ `errors.ts:22` 有 `VERSION_IMMUTABLE: 409`，还有两支测试守着。**拿不存在的先例论证取舍＝整条论证链作废**。
3. 「`design.md §9（分层：apps/web 只做…）」⇒ §9 其实是「CLI 设计」，全文零「分层」二字。

**为什么会犯**：写 FR 时优先按「这个设计应该长什么样」推，而不是按「仓库里现在长什么样」查。跨项目经验会串味。

- 任何 spec / PRD / 设计文档里出现「沿用既有 X」「承 Y 纪律」「参照 Z 先例」「与 A 同型」时，**逐条 grep 一次再落笔**，锚点写成 `文件:行号` 或至少 `文件 §节号`。
- 计数类断言必须**同时写扫描根与深度**，否则不可复算（我写过「子目录 39/29/18」，任何「根×深度」组合都凑不出这三个数）。
- 写「引用 A 的说明」时，用反向 grep 确认 A 真的那样写，别凭印象。

**代价**：规格是实现轮的施工图，一处假引用会被照抄成错代码，越晚发现返工面越大。

## 二、「假引用」的第五形态：文件系统态冒充版本库态

校验「某凭据是否真实存在」的闸，若查的是**磁盘**（`existsSync` / `globSync` / 目录遍历），则**未跟踪文件照样让它通过** —— 未提交的文件与已入库的文件在磁盘上毫无二致。

实测：`tests/spec-claims.test.ts` 的 ✅ 行凭据判据走 `globSync`，一条 ✅ 靠一个**从未进过任何一次 commit** 的组件文件成立（`git cat-file -e HEAD:<path>` 不存在）。

- **为什么它是新的形态**：已登记的假引用都是「引用了**不存在**的东西」，grep 一返空就暴露。这一次是「引用了**真实存在、却只在我本机上**的东西」——**人工复查抓不住**：读起来完全成立、文件也能打开、类型也对，只在「别人 clone 下来」时才破产。
- 任何判据问「X 存在吗」时，先问「我指的是**磁盘上有**还是**版本库里有**」。验收表、台账、凭据清单这类东西语义上永远是后者。
- 实现上用 `git ls-files`（索引视图，含已暂存）而非 `ls-tree HEAD`：后者会把「写好 spec、尚未 commit」的正常开发顺序判红。**判据要卡的是「从未纳管」，不是「尚未提交」。**
- 与 `allSourceFiles`（磁盘索引，用于检索代码文本）**故意不同源**，两个索引混用就是缺陷本身。
- **造变异腿必须造「磁盘有、版本库无」的样本**：喂虚构路径**证明不了任何收紧** —— 虚构路径在磁盘视图下也不存在，旧闸照样能抓，两道闸都会红，测不出差异。本轮据此造了真实的临时未跟踪文件，并显式断言「文件确实在磁盘上」且「确实不在 `TRACKED` 里」作前置自证。
- **构造不出样本的判定口**（如依赖 import 时冻结的索引），要在测试文件里**登记缺口与构造不了的原因**，不要假装覆盖，更不要拿当前工作树的偶然状态当样本 —— 那会得到一支**随并行会话提交而变红**的用例。

## 三、判「查无」需要多路径确认

我曾把一条已交付的测试断言记成「在仓内查无」，并据此写进两份台账、还排了「待补」的工。事实：断言存在于 `core-db.test.ts`，而规格凭据列点名的文件是 `m8-ledger-schema.test.ts`（那里面放的是**结构代理**）。我 grep 了规格点名的那个文件，返回空，就写下「在仓内查无」。

**根因**：「查无」听起来像全局断言，实际只是一个**单点检索**的结论。

- 判某物**不存在**之前，至少换**一个独立检索面**再确认（另一个文件、另一个目录）。换了仍空，才可写「在仓内查无」；只查了一处，只能写「**在该处**查无」。
- 规格把两条凭据写进同一格、而它们分处不同文件时，先把两者**拆到各自的锚点**再动手。
- 已经写成「查无」的登记，落地前用 `grep -rl <核心标识> <多个目录>` 复核一次；发现错了要**显式订正并说明错因**，不要悄悄改掉 —— 错因比结论更值得留在日志里。

**代价**：一次不存在的欠账进了两份台账，若不更正，会有人去「补」一条已经存在的测试。

## 四、命令与注释里的「自指」

**文档里的自指**：把校验命令**原样写进文档**后，这条命令会扫到它自己那一行 ⇒ 口径自毁。实例：检查「v0.2.1 有没有侵占 RF 编号 `1-7`」写成 `grep -n '1-7' docs/dev-plan.md` 放进文档 ⇒ 恒返回 1。改用字符组 `grep -n '1[-]7'` 才归零，**且注释里绝不能再复写那个裸串**（我第一版注释写了，立刻又被扫到，仍是 1）。

**注释里的自指（发生在修复动作本身）**：测试文件头注释里写了完整 glob `packages/*/src/**/*.test.ts`，其中「星号紧跟斜杠」正是 JS 块注释的闭合符 ⇒ 注释提前结束，后半截 glob 被当代码解析，报 `Unexpected "."`。修的时候我在新注释里写「那个 `*/` 提前闭合了块注释」—— **把闭合符原样写了出来，立刻又闭合一次**。

- **通法**：凡是要展示「会被解释器吃掉的字符序列」（glob 的 `*/`、正则量词、反引号、字符串定界符），一律**用尖括号占位或改用描述性文字**。需要举反例时放进反引号**并不安全** —— 反引号挡不住注释闭合符。
- **判别信号**：报错位置落在**注释行内**，且指向一个标点符号（`.`、`?`、`*`）而非标识符 ⇒ 几乎总是块注释被提前闭合。
- 改完必须**立刻重跑**，别靠肉眼。

**跨文档传播**：文档 A 引用文档 B 的某处过时断言，改完 B 后**没回头改 A**，A 就成了「假现状」的传播源。⇒ 改完任一文档后**全局 grep 被它纠正过的那个说法**；变更日志里的历史陈述按「日志不回改」保留，但要追加「⚠️ 订正」而不是留着不管。

## 五、按锚点词 find 规格那一行几乎必然取错行

在规格/文档文本里用 `.find(l => l.includes(marker) && l.includes('→'))` 定位「声明某个契约的那一行」，**几乎必然取到错误的一行**，因为**版本行会复述自己这一版改过的每一件事**。

实测：`agentPayload.test.ts` 要找 m3 规格里 `ai_recommend_call` 的键闭集行，marker 是 `FR-9.1-b`。m3 规格**第 10 行就是版本行**，它写着「v0.6 → v0.7：… ＋ **新增 FR-9.1-b**」⇒ marker 命中、箭头也命中、`.find()` 返回版本行 —— 而版本行里一个键名都没有 ⇒ 「实现 ⊆ 规格」那半边**恒红**。⚠️ 这条红**在 HEAD 上就存在**；若当时顺手「改规格迁就测试」，就会把规格写坏。

- **通法**：条件必须**再加上被检对象自己的标识符**（marker ＋ 箭头 ＋ kind 名，三条同时成立），并把查找抽成具名函数。
- **必须补一支变异腿**：用「版本行」当诱饵放在真行前面，断言仍取到真行；同时用一个**不存在的** kind 名作反证，证明新增条件在做事而不是摆设。
- **为什么这类坑最难自查**：`版本行 | 摘要行 | 变更清单 | changelog` 是**唯一一处会合法地包含全文所有专有名词的地方**。凡需要「某个专有名词只出现在一处」的判据，都要先确认那个词不会出现在这四类行里。

**同族的第二个形态**：屏摄当证据却不核指纹 —— 两张本该不同的图**逐字节相同**，因为脚本里「找含『工具链』二字的按钮」那一步空转、根本没切状态。⇒ **任何「产出多份产物」的脚本，末尾必须有一道指纹核对**（`shasum | sort -u | wc -l` 应等于产物数）。**共同根**：先核对象，再核结论。

## 六、逐字照抄源数据时，字段里的「语义前缀」是数据的一部分

我把 owner 提供的 HTML 指南全量抄进 spec，抽取脚本顺手做了 `re.sub(r'^(产出|练习|跳过)：', '', out)` ——「把标签剥掉、只留内容」看着是洁癖，实际是**删数据**。

源数据里那一栏的前缀是三种**语义相反**的东西：`产出：`（可交付物）· `练习：`（动作要求）· **`跳过：`（本段明确不学什么）**。实测分布 产出 10 / 练习 2 / 跳过 2 / 空 7。

**后果**：Go 熟悉第 3 段原文是「**跳过**：goroutine 深入模式、pprof、反射、cgo、gRPC 与微服务框架」。剥掉前缀后入库成「产出：goroutine 深入模式…」，界面会把**「本段不学并发」显示成「本段产出并发模式」—— 方向完全相反**。

- 照抄源数据时**先分类统计每类前缀的条数再动手**。前缀种类 ≥2 时，默认它们承载语义，不是排版。
- 抽取脚本的输出必须能被**反向核对回源**（逐格比对附件原文的检查器在变异腿里钉住这条）。
- **源里没有的字段不许自撰填充**：21 段里有 7 段不带产出栏，正确做法是显式写 NULL 且界面整行不渲染；填「继续学习」是**用源的口吻说源没说的话**。
- 「空」与「未知」也要分开：`长期` 是合法取值，不是 NULL。

## 七、文档里的「实测数字」必须与实跑绑定

**① 规格/计划里的实测数字没有闸 ⇒ 改文档与改代码可以无声分叉。**
本例：P1 出口条件写着「`lang_topics` 节点数 = **72**」，而单测只钉了两个**分项**（Python 45 / Go 27）⇒ **72 这个总数只活在注释里**。⇒ 改文档（72→71）闸不红；改代码（45→44）闸也不红。
⇒ 凡是写进规格/计划的**实测数字**（条数 / 占比 / 节点数 / 版本号），都必须有闸把「文档写的」与「实跑的」绑在一起；且**要断两个方向** —— 改文档红、改代码红（后者要真动一次库/产物，只喂假值不算数）。补法照抄现成判据的手法：§3.1 表数复算 17 由 DL-26 守着，它正是**从正文读出那个数**再与实跑对账。

**② 同一行里「旧值」与「新值」并存 ⇒ 按「第一个出现的数字」取必然取错。**
规格：「订正前是 `44 ＋ Go 全 34 ＝ 78`，**订正后是** `45 ＋ Go 语言知识点 27 ＝ 72`」；计划：「**原写 78**，本轮按实测订正为 72 …… **实测** …… = 72」。
⇒ 行内取数必须**锚在带语义的标记**上（「订正后是」／「实测」／「「lang_topics 节点数 = N」），不能靠「第一个出现的 72」。**反证腿**要专门钉这条：断言「旧值同在时仍取新值」。

- 与「按锚点词 find 取错行」同族但不同形：那条是**不同行**之间选错，这一条是**同一行内**取错。
- 与「总数对 ≠ 拆分对」互补：那条防**拆分**错位，这条防**总数与实跑**脱钩。
- 文档里被订正过的数字，旁边几乎一定留着**旧值**（人不会删掉订正痕迹）⇒ 这是常态，不是例外。

**apply when**：任何从规格/计划/README 文本里**解析数字**来当判据的地方；任何把实测数字写进文档、却没让闸读文档的地方；任何「文档里的数」与「代码里的数」本该相等、却各写一遍的地方。

## 八、随时间派生的量必须自带参照日

存档里存了 `age_days`（距源上次推送多少天），守卫却按「运行闸的那天」复算它 ⇒ 每次重新采集，合法变大的 `age_days` 就与旧参照日对不上 ⇒ 单测误红。**源没变，是参照日变了** ⇒ 那条红是**假的**。

- 存档里凡是**随时间派生**的量（天数/年龄/倒计时），**必须自带一个参照日字段**，且那个参照日要等于存档自己的采集日（让清单的 `collected_at` 直接取自它 ⇒ 天生对齐，不会「夹生」）。
- 闸复算时**按块自报的参照日**，不按「跑闸当天」；外部日期只作**显式覆盖**。缺参照日 ⇒ 单独一条规则报红，**不许悄悄退回「用今天」**。
- **验收要两头都验**：合法重采（参照日 + 派生量一起挪）⇒ 0 违规；只挪参照日不挪派生量 ⇒ **仍红**。第二条才证明「参照日真的被读了」，否则那条规则可能是摆设（恒绿）。
- 同族：闸若拿快照比活体，红的可能是**参照物**而不是被测对象。派生量与参照日**放在同一个对象里**比放两处好。

## 九、闸的「规则说明」本身也要过闸：描述形态，不复写样例

上一条讲的是**被扫的文本**里不能出现被检的字面量。这一条是它的镜像：**闸自己产出的说明文字**也可能带着被检形态，于是被自己抓到。

实例（本轮实测）：给「记忆导出」写脚本时，我在生成的 README 里写了一句「本 README **零绝对路径**（`/Users/`、`/home/<用户>`、`C:\\` 全零命中）」来解释这条规则 —— 而 README 自己就在被同一条「零绝对路径」检查扫描 ⇒ **它把自己的说明判成了违规**（导出当场失败）。

**通法**：
- 闸的规则说明里**只描述形态、不复写样例**：「用户目录形态、home 目录形态、Windows 盘符形态三者全零命中」—— 读者看得懂，检查也抓不到自己；
- 同理适用于任何「**禁止出现 X**」型规则的说明文字：正则、路径片段、命令样板都别原样写进「说明这规则怎么用」的那段；
- ⚠️ 判别信号：**闸在扫自己写的文件时红了，而那行并没有违反它想表达的规则** —— 这就是「说明文字自带违规形态」的典型现场；
- 配套：闸的**输出件**也要能重跑。若闸失败在最后一步，前面已写出的半份产物会**让下一次运行被「目标目录不干净」卡住** ⇒ 要么先写带标记的清单文件，要么让清理条件接受「只有本脚本管的那几样」这一种半成品状态（判定要严：多一个不认识的文件就拒绝清理）。

**apply when**：任何**会扫描自己产出物**的检查器（导出器、生成器、格式化器）；任何在「规则说明」段落里引用了被禁形态的闸。
