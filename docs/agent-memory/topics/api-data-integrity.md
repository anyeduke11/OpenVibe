# 公开接口采集的完整性纪律

Type: incident-lesson

**一句话**：批量采集最容易出的不是「报错」，而是**静默少数据**。接口返回 200、脚本不抛错、日志看着正常，但落库条数比接口 total 少——这类缺陷不主动对账就发现不了。

## 一、分页上限：先实测，别信参数名

- 实测：东财 clist 接口把 pz 封顶在 100，传 500/1000 也只回 100 行。ETF 1659 只因此只采到 100 条。
- 通法：任何「一次拉 N 条」的参数，都要用一次真实请求验证返回长度；发现被截断就把分页责任收到客户端。
- 分页循环的终止条件要用「累计条数 ≥ total」，不能靠「本页为空」——后者在 total 口径错误时会死循环或早停。

## 二、排序漂移：分页期间排序键会变

- 实测：按涨跌幅（fid=f3）排序拉 5563 条，采集期间行情在漂移，同一只股票落到相邻两页，落库只有 5416 条（147 条重复）。
- 通法：批量拉全量必须用**稳定排序键**（代码序 fid=f12），并在入库前按主键去重；重复条数要**显式计数报出**，不能静默丢弃。
- 对账口径：落库行数 == 接口 total。不等就是有重复或缺失，先查这个再往下走。

## 三、占位符脏值：REAL 列会存进文本

- 实测：停牌、退市、无成交的标的，接口返回字符串 "-"；SQLite 动态类型把它当文本存进 REAL 列，后续排序算术直接 TypeError。
- 通法：入库前统一数值清洗——无法解析为数字的占位符一律转 None（表示「数据缺失」）。
- 反向纪律：缺失值落 None，绝不落 0。0 是「确实为零」，None 是「没有数据」，两者在风控与报告里结论完全不同。

## 四、参数编码：裸 + 可能被解成空格

- 实测：查询串里的 fs=m:0+t:6，若服务端做 form 解码，加号会变空格导致查不到数据。
- 通法：查询参数**全量百分号编码**，别为可读性留半编码；编码前后各验一次返回条数。

## 五、连接中断：连续翻页会被服务端断连

- 实测：连续翻页中途出现 RemoteDisconnected。
- 通法：requests 加重试 + 退避（3 次、递增间隔）+ 页间小延时；重试耗尽仍失败必须抛错，**禁止静默返回空**——采集失败必须留痕，否则上层会以为「今天没数据」。

## 六、日期窗口：单日窗口查不到「即将发生」的事

- 实测：IPO 报表按 APPLY_DATE 查，只有已发生记录；未来事件在另一个报表（事件日历表）里，且该表过滤语法不生效，需全量拉取后本地过滤。
- 通法：查「未来窗口」前，先确认数据源的时间字段语义；多表合并时按业务主键合并，不要按日期过滤各表后再拼。

## 七、同一数据源的不同端点，精度口径可能不同

- 实测：东财 clist（/api/qt/clist/get）返回已还原的价量；ulist（/api/qt/ulist.np/get）返回**未还原的整数**——股票价格差 100 倍、ETF 差 1000 倍，百分比字段差 100 倍，量额同量纲。用 ulist 做定点刷新会静默写入错量纲的值（144294 元/股、4140 元/份）。
- 通法：**不要凭接口名猜精度**。拿同一批标的做同日留档逐字段对比（clist 原始响应 vs ulist 原始响应），用比值反推标定规则，再把规则写成函数 + 单元测试（实测标定：价格 ÷10^f1，f1 = 小数位，股票 2 / ETF 3；百分比 ÷100；成交量额原样）。
- 配套纪律：定点刷新写入用「None 不覆盖既有值」的 upsert，否则本次没取到的字段会把历史值抹成空。

## 八、双源比对：两侧必须同窗刷新，否则差异里混着采集时间差

- 实测：iFinD 日频指标在收盘前返回的是「上一收盘」口径；本地快照采集于盘中。两侧时点不一致时，PE/PB/市值差异里有一部分是时点漂移，不是源差异。
- 通法：比对前先刷新本地侧到同一时刻；报告里写明两侧各自的时点。容差（实测 1%）只是兜底，不是替代。

## 九、外部结构化文本响应（LLM / connector 的表格文本）的解析纪律

- 实测：同花顺 iFinD 的 markdown 表格，**相邻两张表之间可能没有空行**——按「空行切表」会把两表并成一表，第二张表的数据列被整列丢弃（净值解析出 0 行、债券评级取到了收益率列）。表头首格重复出现，是新表开始的可靠信号。
- 实测：列名包含易混词（`单位净值` 与 `单位净值币种`、`累计单位净值` 并存）时，按包含匹配会取错列。
- 通法：表格解析要能处理「无空行分隔」与「列名包含关系」两种形态，解析后必须用样本断言行数与关键字段值（不是只断言不抛错）。
- 通法：单位必须显式换算（万亿 / 亿 → 元），不能直接当数值用。

## 十、采到了却没落库：字段在响应里，但代码只挑了一部分用

- 实测：东财板块清单（clist fs=m:90+t:2）每行同时返回 f3 涨跌幅与 f20 总市值，采集代码只把 f12/f13/f14 落进 `securities` 表，f3/f20 直接丢弃。结果：板块清单条数对得上（496+531=1027），但库里**没有任何板块涨跌幅**，下游「板块轮动」无从复算——上层报告只能写「数据缺失」，而真实数据其实一直在响应里躺着。
- 通法：落库前对一遍**接口请求字段列表 vs 实际落库列**，请求了却没用的字段要逐个说明理由。批量采集的「条数对账」只证明行数对得上，不证明**列**齐全。
- 判据：条数对账之外，再加一条**字段级对账**——采集器请求的每个字段，都能在落库表里找到对应列，或有明确的丢弃理由。
- 附带坑：把板块代码写进 `securities` 表（该表本意是存个股基础信息）会让行业归属字段恒为空，个股→行业的映射彻底断掉。板块行情要单表存放，别混进个股表。

## 十一、排名类输出：缺失值不能参与排序，也不能占榜位

- 实测：生成「跌幅前 10」时按 `(pct_chg is None, -pct_chg)` 排序，343 只退市/停牌股的 `pct_chg` 为 None，被排到末尾并**整段占据了跌幅榜**，真实的 ST豆神（-12.61%）等 10 只全部被挤出榜单；榜单里同时出现 `None` 字面量而非占位符。
- 通法：**排名类输出先过滤缺失值**，只让有行情标的参与排序；同时把被过滤的数量**显式声明**（「无涨跌幅标的：343（退市/停牌等，不参与涨跌幅排名）」），不能静默丢弃。
- 缺失值在表格里显示「—」，不显示 `None` 字面量——`None` 是 Python 内部值，落进面向人的文档等于把实现细节泄漏给读者。
- 配套：标题这类**随产物类型变化的字段**不要复用模板。晚报复用晨报模板却写死「# 晨报」标题，产出的是一份自称晨报的晚报——模板复用时，标题必须随 kind 参数化。

## apply when

任何对接公开接口做批量采集落库的任务。核心自检句：**落库条数对得上接口 total 吗？对不上时，重复与缺失各是多少？写进去的数值量纲对吗？**
