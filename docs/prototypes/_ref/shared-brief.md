## 1. 产品事实（设计的事实来源，不得改写）

### 1.1 这是什么

- **OpenVibe / 灵典**：vibe coding 的**标准化工作台**。本地优先——全部数据在一个 SQLite 文件里（`~/.openvibe/data/openvibe.db`），
  Web 服务只监听 `127.0.0.1:8787`，关掉进程就什么都不再动。没有账号、没有云、没有后台常驻。
- **用户**：中文社区的 vibe coding 开发者。个人起步，架构预留小团队。日常使用频率高（每天 5–10 分钟，注入/组包时一天多次）。
- **它替用户干的事**：把「同一个坑给 AI 讲三遍」这类话收进一个本地库，攒成**标准包**，一条命令写进各个项目的规则文件，
  并且**知道哪些文件是你手改过的**。

### 1.2 核心闭环 = 标准化飞轮（界面必须让这条线看得见）

```
① 沉淀资产            ② 组装标准包           ③ 注入项目
提示词 / 术语 /        挑选资产 + 流程模板      openvibe sync 写入
Skill / 流程模板  →    → 带内容指纹的包    →   9 个文件到项目目录
      ▲                                              │
      │ ⑤ 复盘回流                                   ▼
      └──── 新术语 / 新提示词草稿 ←──────────  ④ 按流程开发
             （带来源反链）                     阶段 · 清单 · 看板 · 开发日志
```

「飞轮圈数」口径：同一项目「有导出包 → 有注入记录 → 有 ≥1 条回流资产」记 1 圈，按项目去重。

### 1.3 对外承诺（信任底线，界面必须承载，不许美化掉）

| 承诺             | 界面/文案里的真实表达                                                                                          |
| ---------------- | -------------------------------------------------------------------------------------------------------------- |

| 覆盖前必定备份   | 原文件先备份到 `<项目>/.openvibe/backup/<UTC 时间戳>/`                                                         |

### 1.8 v0.2.0 产品方向（设计要**吸收原则**，不要假装功能已上线）

- 定位读法升级：从「资产管理器」到「**意图 → 项目上下文的编译器 + 分发器 + 反馈回路**」。评价轴从"库里存了多少"换成"你的项目真的变好了吗"。
- **成长阶段 F0–F3**（定义在「用户 × 资产类型 × 任务」上，按模块各有一档，不是账号等级）：
  F0 跟随者「别让我选，告诉我做什么」/ F1 实践者「我想知道为什么」/ F2 作者「我要写自己的标准」/ F3 定标者「我要定义别人怎么判断」。
- **渐进披露五条红线（产品红线，任何方向都必须满足）**：
  1. **永不隐藏数据** —— 折叠/排序/预填可以有差别，「查看全部」永远一键可达
  2. **永不隐藏错误** —— 失败、漂移、冲突在任何阶段都看得见，不为了「简单」吞错
  3. **阶段可见且可解释** —— 界面上永远有一句「为什么你现在看到这个」（可点开）
  4. **一键越级** —— 任意页面可切到「专家视图」，并按模块记住该选择
  5. **升级不打断** —— 升级提示是一次性卡片，不是模态框
- 本机事件台账：本机、不出网、可清空；与「匿名统计」**不是一回事**（设置页两节并排，一个永不出网、一个默认关）。
- 设计含义：一切「简化」都必须可展开、可解释、可越级；**不得**用漂亮界面掩盖错误与风险。

## 3. 硬约束（任何方向、任何文件都不得违反）

1. **单文件 HTML**：内联 CSS/JS，无外部 JS 库；**不依赖网络**（字体用系统栈；若用 webfont 必须有等价兜底栈，断网不塌）。
2. **不用 emoji 当设计元素**（图标 / 头像 / 占位 / 装饰一律 SVG 线性图标：`stroke 1.6–1.8`、`currentColor`、圆角端点一致）。
3. **无 AI 土味**：紫蓝渐变、白底紫渐变、彩虹/全息渐变、玻璃拟态、暗底霓虹发光、卡片套卡片、左侧 4px 彩条卡片、
   「居中大 hero + 三栏特性卡」模板、装饰性 quote、抽象几何 blob —— 一律禁止。
4. **可读性**：正文对比度 ≥ 4.5:1（尽量 ≥ 7:1）；次要文字 ≥ 4.5:1；**不用纯黑 `#000`**；正文最小字重 400；
   中文正文行宽不超过约 68 个字符（长文页收窄阅读列）；数字与表格列 `font-variant-numeric: tabular-nums`。
5. **状态三通道**：颜色 + 文字 + 图形（图标或形状），不得只靠颜色表达一致 / 漂移 / 新增 / 失败 / 警告。
6. **交互态齐全**：默认 / 悬停 / 按下 / 聚焦（`focus-visible` 2px 实心环 + 2px offset）/ 禁用；键盘可达，`Esc` 关浮层。
7. **动效克制**：150–200ms，`cubic-bezier(.2,.7,.3,1)`；`prefers-reduced-motion: reduce` 下全关。
8. **响应式**：桌面优先，但必须有平板（768–1023px）与手机（<768px）断点。手机端导航不得消失（转顶栏/底栏 + 抽屉），
   表格转卡片，任何断点都**不得出现横向滚动**。
9. **不改业务语义与路由**：八个业务区都能找到；只改变它们的组织方式、层级与呈现。
10. **权限边界必须说清**：Web 只读展示 + CLI 是写盘唯一通道（页面上要有这句话的位置）。

## 4. 交付物 A · 可交互原型（`...-可交互原型.html`）

一个可点击走通的单页应用，**至少覆盖下面 12 个屏**（可更多，不可少）：

1. 工作台 / 概览（飞轮面板 + 下一步 + 活跃项目）
2. 提示词库（列表 + 过滤 + 编辑器/详情，含版本历史与 diff）
3. 术语库（表格 + 学习路线 + `TERMS.md` 预览）
4. Skill 台账（列表 + 扫描/更新状态）
5. 流程模板（模板卡 + 阶段与检查项）
6. 项目工作台（列表）
7. 项目详情（阶段条 + 检查清单 + 任务看板 + 开发日志 + 回流入口）
8. 标准包（列表 + 包明细：导出历史 / 注入历史 / 指纹）
9. 组包向导（五步，可前进后退，第 5 步含产物预览与近似上下文量）
10. 设置（服务信息 / 种子内容 / 预置包 / 匿名统计 / 向导 / 备份说明）
11. 开箱三步（可跳过，第三步含命令复制与「未检测到 lock」的等待态）
12. 关键状态页：空态、加载态、错误态、**冲突处置**（DRIFT 三选一：以包为准 / 保留本地 / 跳过）

**必须真实可交互（不是贴图）：**

- 业务区切换（导航可用，当前项有明确激活态）
- 搜索/过滤真的会筛内容；分类筛选 chip 可切换
- 详情/编辑器/抽屉可打开可关闭（`Esc` 可关，遮罩点击可关）
- 分段控件（tabs / segmented）可切换，切换后内容真的变
- 组包向导可 上一步/下一步，步进条同步
- 任务看板卡片可移动（按钮或键盘，至少 2 列之间），移动后列计数变
- 阶段条可切换当前阶段，清单完成度随之变化
- 至少一个开关（如设置页「匿名统计」、主题切换）有真实状态变化 + 反馈
- 至少一处 toast/结果反馈，一处禁用态，一处加载骨架，一处空态带「下一步 CTA」
- 冲突处置：三档策略可选中，选中后给出「将执行什么、会备份到哪里」的如实说明

**自检（交付前逐条过）**：无 emoji；无横向滚动；手机断点可用；键盘可达；焦点态可见；对比度达标；数字对齐；文案全中文；页面无 `TODO`。

## 5. 交付物 B · 无限画布（`...-无限画布.html`）

**必须从模板改造**：先完整读 `redesign/_ref/infinite-canvas-template.html`，用它的 API 与三层架构，不要自己另写一套画布。

- 画布容器占满 `100vw / 100vh`；元素可拖动；**所有定位用 `below() / rightOf() / maxY() / maxX()`**，禁止硬编码猜高度。
- Row 1 **项目介绍**：大字项目名 + 一句话定位 + 关键词标签 + 飞轮链路图（用 `addDiagram`）+ 2–4 张卡片（用户画像 / 现状问题 / 与竞品差异 / 这次重设计解决什么）。
  必须回答清楚：**是什么、给谁用、解决什么问题**。
- Row 2 **设计系统**：全部包在 `addDesignSystemCard` 里 —— ① 色板（`addColorSwatch`，token 名 + hex，**必须与本方向实际用的值一致**）
  ② 字体排版（`addTypeSample`，真实渲染的字号阶梯）③ 组件样例（按钮/输入/chip/表格/卡片，含状态）④ 间距与圆角（可选）⑤ 交互状态枚举（可选）。
  卡片横排 3–4 张，同一 Y 起始，间距 20–40px。
- Row 3 **设计稿**：把第 4 节那 12 个屏**按用户操作链路从左到右**排列成页面设计稿（桌面尺寸 1440×900 或 1280×800，等比缩放进画布），
  用便签/连接标注跳转关系与关键交互。页面内部：**不用画布特效、不用 emoji、干净矩形结构**（截图进 Figma 可编辑）。

## 6. 产出规范

- 只写你自己的两个文件，输出到 `redesign/` 目录；**不要修改仓库里任何既有文件**（尤其不要动 `apps/`、`docs/`、`content/`、`redesign/_ref/`）。
- 文件名（严格照抄，`V1` 是版本号）：
  - `redesign/V1 OpenVibe-方案A-账本-可交互原型.html`
  - `redesign/V1 OpenVibe-方案A-账本-无限画布.html`
  - `redesign/V1 OpenVibe-方案B-运行台-可交互原型.html`
  - `redesign/V1 OpenVibe-方案B-运行台-无限画布.html`
  - `redesign/V1 OpenVibe-方案C-成长路径-可交互原型.html`
  - `redesign/V1 OpenVibe-方案C-成长路径-无限画布.html`

- 代码体量参考：可交互原型 1200–2400 行、无限画布 700–1500 行；用 CSS 变量集中管理 token，不要散落字面量。
- 原生 HTML/CSS/JS（无框架）：DOM 用模板字符串渲染，事件用委托，避免内联 `onclick` 满天飞。
