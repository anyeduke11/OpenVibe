## 对「四件必选」的直接冲击（三条，全部有实测支撑）

1. **退出码不可信**：codebuddy 在未登录时 **exit 0**。⇒ 派发层不得以退出码作为唯一成功判据，必须叠加「输出非空 + 结构化完成信号」。
2. **失败可能无限重试而非快速失败**：claude 带工具调用时既不报错也不退出（420s 才被外部 kill）。⇒ 派发层必须自带超时与心跳，不能依赖 agent 自己退出。
3. **JSONL 不是纯 JSONL**：qwen 的 stream-json 混入一行非 JSON 告警（`Skill command '/review' was renamed ...`）。⇒ 归一器必须**逐行容错跳过**，不能整段 `JSON.parse`。

## 对「待定契约」的两条修正建议（待 owner 裁，不擅自改 PRD）

- **事件 `ts` 必须由中台接收时打**。实测 qwen 全部事件只有 `uuid` / `session_id`，**无时间戳**；只有最终 `result` 带 `duration_ms`。原提案 `{ seq, ts, kind, sessionId, payload }` 里的 `ts` 无法从 agent 取。
- **`result` 信噪比高于预期**：qwen 的 `result` 事件带 `is_error` / `stop_reason` / `total_cost_usd` / `permission_denials`。⇒ FR-3.0-1 的 `quota_cost` 字段**有真实数据源**，C-19 不是空字段。

### 本轮新发现（6 条，均有实测）

1. **工作区必须是 git 仓**：codex 在非 git 目录直接 exit 1（`Not inside a trusted directory and --skip-git-repo-check was not specified.`）。⇒ 探针工作区与将来的派发工作区都要先 `git init`，否则会把「环境缺省」误报成「协议缺失」。
2. **claude 的 JSON 声明缺 `--verbose`（已修，复跑验证）**：`--print` 模式下 `--output-format=stream-json` 必须配 `--verbose`。已在种子 `jsonFlag` 补上（2026-11-20，[`seed-agent-registry.ts`](../packages/core/src/db/seed-agent-registry.ts)），新库复跑后：① 「参数报错」消失；② L1-2 从「取不到 session 标识」变为**能取到**（L1-3 因此从 ⭕ 跳过转为实际续跑尝试）；③ 剩余失败全部是超时，绑定第 6 条的模型配置。
3. **resume 旗标位置因 CLI 而异**：codex 是子命令链（`exec resume <id>`）、opencode 的 `--session` 必须在 `run` 之后、qwen 的 `--resume` 在 `-p` 之前。注册表没有「位置」列 ⇒ 探针按两发择优；若进产品派发层，需在注册表补位置声明或按 CLI 白名单。
4. **两种假绿**：codebuddy exit 0 + stdout 空；且 401 时仍吐 5 行合法 JSON（只有 init 事件）。⇒ L1-2 判据已改为「有 session 标识**且**有任务回显」，两者缺一即红。
5. **真错可能写在 stdout 事件流**：codex 的错误是 `{"type":"error","message":"..."}`，stderr 全是 otel 噪声。⇒ 归一器与诊断层不能只读 stderr。
6. **claude 补 `--verbose` 后暴露的真因是模型配置**：单独执行 `claude -p "..." --output-format stream-json --verbose`，stderr 出现 `[claude-code:unrecognized_model] {"model":"deepseek-flash[1m]","query_source":"sdk"}`，随后挂到超时；同期 stdout 已在吐合法事件行（`hook_started` / `hook_response`，含 `session_id`）。⇒ claude 的 JSONL 结构面**有证据**，缺的是可用模型凭据，不是协议。
