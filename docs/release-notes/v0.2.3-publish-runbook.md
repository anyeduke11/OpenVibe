# v0.2.3 发布操作手册（runbook）

> 执行人：**owner**（唯一需要 npm 凭据的步骤是第 5 步；本机 `npm whoami` 实测 ENEEDAUTH）。
> 每步都有「预期输出」——不符即停，不要带病前进。发布完成后回到本文末尾的「发布后收尾」四件。

## 0. 前置检查（工作树干净度）

```bash
cd /Users/duke/Documents/OpenVibe
pnpm lint && pnpm typecheck && pnpm test        # 三闸全绿（并行会话在编失败须先收）
pnpm docs:check                                  # 退出码 0
pnpm seed:check                                  # 种子闸绿
git status --porcelain                           # 确认本笔要提交的文件清单，无他人禁区文件混入
pnpm ownership:check                             # 提交归属核验（多会话纪律）
```

预期：三闸 + 两检查全绿；`git status` 只含本次发布的改动面。

## 1. 包名与 registry 复测（发布前最后一眼）

```bash
npm view openvibe-cli version                    # 预期：404（名字仍可用）
npm view openvibe version                        # 预期：1.0.0（无关包仍占着 openvibe）
grep -n "PUBLISH_NAME = " scripts/build-cli.ts   # 预期：'openvibe-cli'（批次 A 裁决）
```

任何一条不符 ⇒ 停，回 spec `v023-a-launch.md` §8.2 重新裁决，不要现场改名。

## 2. 构建

```bash
pnpm pkg:cli        # 预期回显：openvibe-cli@0.2.3 → apps/cli/pkg/（… 0 条 esbuild 警告）
```

预期：`apps/cli/pkg/package.json` 的 `name` 为 `openvibe-cli`、`version` 为 `0.2.3`；
`dist/cli.js` 约 5,096 kB、775 模块。

## 3. 预演（零网络，凭证落档）

```bash
cd apps/cli/pkg && npm pack --dry-run
# 预期：name: openvibe-cli / version: 0.2.3 / 82 files / 1.7 MB
# 记录 shasum 行（sha1）——发布说明「测量口径」表用它
shasum -a 256 openvibe-cli-0.2.3.tgz 2>/dev/null || true   # 若先真 pack 了再核对 sha256
node dist/cli.js --version                                  # 预期：0.2.3
cd /Users/duke/Documents/OpenVibe
```

## 4. 冒烟（打包产物三态，60 秒）

```bash
pnpm verify:matrix --run --bin apps/cli/pkg/dist/cli.js
```

预期：serve / sync / diff / verify / scan / clean 六行 pass，五行 manual（人工环境，如实标注）。
任何 FAIL ⇒ 停，先修再发。

## 5. 发布（唯一需要凭据的一步）

```bash
npm login                       # 浏览器 OTP 流程；npm whoami 确认登录名
cd apps/cli/pkg
npm publish --dry-run           # 最终预演：核对 name/version/files 与第 3 步一致
npm publish                     # 若开了 2FA：npm publish --otp=<六位码>
cd /Users/duke/Documents/OpenVibe
```

预期：`+ openvibe-cli@0.2.3`。**publish 即 D15 证伪线起点**（tasks.md §5 既有裁定：
起点 = `npm publish` 成功当日）。

## 6. 发布后验证（三条，全部要过）

```bash
npm view openvibe-cli version                   # 预期：0.2.3
npx -y openvibe-cli@0.2.3 --version             # 预期：0.2.3（走 npx 缓存的真实安装路径）
cd apps/cli/pkg && npm pack && npm i -g ./openvibe-cli-0.2.3.tgz && openvibe --version && openvibe verify --help
                                                # 预期：0.2.3；verify --help 正常（装出来的命令叫 openvibe）
cd /Users/duke/Documents/OpenVibe
```

可选腿（真实 ABI 失败留证）：在一台没装过本包的机器/容器上故意用不匹配的 Node 大版本安装，
把报错原文贴进 `docs/devlog-evidence/`——核对诊断是否命中三要素（不复现也不阻塞发布）。

## 7. 发布后收尾四件（当日完成）

1. **D15 起点登记**：DEV_LOG 追加一条（起点日期 = publish 当日；判据单源 tasks.md §5，不复制）。
2. **release 说明定稿**：`docs/release-notes/v0.2.3.md` 摘掉「草稿状态」头，「测量口径」表按
   publish 当日复跑值刷新（第 3 步记的 shasum、第 6 步的回环验证）；GitHub release：
   `gh release create v0.2.3 --title "OpenVibe v0.2.3" --notes-file docs/release-notes/v0.2.3.md`，
   并把 `openvibe-cli-0.2.3.tgz` 挂为 release 资产（`gh release upload v0.2.3 apps/cli/pkg/openvibe-cli-0.2.3.tgz`）。
3. **README 措辞面清零**（批次 A FR-5）：`grep -n '尚未在 npm\|404\|未上线' README.md` 命中逐条改写；
   首屏「30 秒上手」三条命令在干净路径实测通过后才算清零。
4. **复验矩阵归档**：两平台（macOS + Linux 容器，spec v023-a §8.2 裁决②）各跑一次
   `pnpm verify:matrix --run`，markdown 结果贴进 release 说明「复验矩阵」段，
   原始输出归档 `docs/devlog-evidence/`；「本版未验证的事」逐条翻转或换新理由。

## 回退预案

- publish 后 72 小时内可 `npm unpublish openvibe-cli@0.2.3`（npm 政策允许窗口内撤架）；
  超窗用 `npm deprecate openvibe-cli@0.2.3 "原因"` 标记。
- 回退只撤 npm 架，不影响本地已装用户（他们的数据在 `~/.openvibe/`，与 registry 无关）。
