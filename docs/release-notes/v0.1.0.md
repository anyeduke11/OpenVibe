# OpenVibe v0.1.0 · 发布说明

> 首个可安装版本。包名 `openvibe-cli`（npm 上 `openvibe` 已被占用），命令名 `openvibe`。
>
> **发布状态（2026-09-26）**：真实 `npm publish` **尚未执行**（见「本版本未验证的事」第 4 条）⇒
> 下面三条 `npx` 此刻还装不到，它们是发布后的用法，不是当前事实。

## 装与用

```bash
npx openvibe-cli serve --open                              # 起本地服务并开浏览器
npx openvibe-cli sync ~/your-project --pack default        # 把预置标准包注入项目
npx openvibe-cli diff ~/your-project                       # 查漂移（0=一致 / 2=有改动）
```

要求 Node ≥ 22。全部数据在 `~/.openvibe/`（`data/openvibe.db` + `config.json` + `packs/`），
运行期不需要外网；项目侧只多一个 `.openvibe/` 台账目录与注入出的规则文件。

## 这一版有什么

- **五类资产本地库**：提示词 / 术语 / Skill 台账 / 流程模板 / 标准包，109 条术语、3 套流程模板、
  20 条精选提示词随包播种，首启即有一个可用的 `default` 标准包。
- **标准包注入六个助手**：`CLAUDE.md`、`.cursor/rules/openvibe.mdc`、`AGENTS.md`、`CODEBUDDY.md`、
  `.trae/rules/openvibe.md`、`MINI.md`，外加 `TERMS.md` / `CHECKLIST.md` 与 `.openvibe/pack.lock.json` 台账。
  同一份内容指纹，跨助手一致。
- **漂移看得见**：`diff` 报 `DRIFT`，`sync` 冲突三选一（以包为准 / 保留本地 / 跳过），
  任何覆盖前先写 `.openvibe/backup/`；`--dry-run` 承诺零写入。
- **流程与回流**：项目工作台按模板推进、记开发日志，日志可一键生成术语/提示词草稿并挂来源反链 ——
  飞轮第⑤步是真实端点，不是路线图。
- **Web 九页 + CLI 五命令**（serve / sync / scan / diff / clean），`--json` 契约统一，退出码 0/1/2。
- **退场有闸**：`clean` 删除当前 lock 登记且**未被改动**的受管文件，删除前一律先进 `.openvibe/backup/`；
  `--dry-run` 只出三态计划表零写入，`--force` 才连 DRIFT（注入后你改过的）文件一起删、改后内容先进备份。
- **遥测默认关**：白名单三类事件、五段载荷、不含路径与内容；未配置端点时连上报定时器都不创建。

## 已知局限（装之前就该知道）

- **一项目一包**：`pack.lock.json` 是单包结构，一个目录同时只由一个标准包托管，换包即整包替换，不做多包叠加。
- **整文件管理，无块级合并**：受管单位是整个产物文件；注入后你改过的段落（DRIFT）不会被自动重写，
  退场请用 `clean`（默认只删未改动的受管文件，删除前一律先备份），回滚同理靠 `.openvibe/backup/`。
- **无云同步与账号体系**：团队协作靠 bundle JSON 走 git（导出 → 提交 → 别人 `sync --file`）；
  权限、审批、LLM 密钥托管在 P2/P3。
- **中文 UI 优先**，暂无英文版；种子内容以中文技术术语为主。
- **pnpm 装包需要一次 `approve-builds`**：pnpm 10 默认拒跑依赖安装脚本，会先报
  `ERR_PNPM_IGNORED_BUILDS`（安装器语义，不是打包缺陷）。npm / npx 用户按平台取预编译包，不涉及这一步。

## 本版本**未**验证的事（按未验证处理，不当通过）

- 干净环境走查在 **macOS + Node v26（ABI node-v147）** 上跑通预编译包；
  Windows / Linux 与非 147 ABI 的**装包路径**没有本机证据 —— 三平台 CI 覆盖的是源码构建与五道门禁
  （Lint / Typecheck / Test / Seed check / Bundle check，Node 22），不含 `npm pack` 之后的产物路径。
  **门禁凭据不在本文件抄 run id**（自己给自己背书会循环）：取当前 `main` 的三平台结论用
  `gh run list -L 1 --json databaseId,headSha,conclusion` → `gh run view <id> --json jobs --jq '.jobs[]|"\(.name) \(.conclusion)"'`。
  旧锚点 run `35844980582` @ `3e852c2` 读作 2026-09-23 那次走查的历史凭据，不代表本文件所在的树。
- **注入路径的越界防护在 Windows 上按未验证处理**：win32 主动门控跳过 **8 支** POSIX 语义用例
  （符号链接逃逸、`0600` 权限位、`sync.lock` 与 `clean` 的路径语义），分布 6 个文件、8 个门控调用点：
  `cli/sync` 2 支，`cli/{security,serve,clean}` 各 1 支（`it.skipIf(IS_WINDOWS)`），
  `cli/config` 1 支（`itPosix` 三元 helper），`core/inject/{security,sync-lock}` 各 1 支。
  所以 CI 的**用例数按平台不等**：macOS / ubuntu 各 449 passed，windows **441 passed + 8 skipped**。
