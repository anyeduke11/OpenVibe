## 装与用

```bash
npx openvibe-cli serve --open                              # 起本地服务并开浏览器
npx openvibe-cli sync ~/your-project --pack default        # 把预置标准包注入项目
npx openvibe-cli diff ~/your-project                       # 查漂移（0=一致 / 2=有改动）
npx openvibe-cli verify ~/your-project                     # 三方一致性核验（0=自洽 / 2=有偏差）
```

要求 Node ≥ 22。全部数据在 `~/.openvibe/`；运行期不需要外网；项目侧只多一个 `.openvibe/` 台账目录。

## 自 v0.1.0 资产以来有什么（按里程碑）

- **M4 技巧库**：真实场景的做法与反例入库，`PLAYBOOKS.md` 随包注入。
- **M8 Agent 接入层**：`POST /api/agent/ingest` 五类回流（一律 pending、人工确认才生效）、
  `GET /api/projects/:id/context` 聚合上下文（预算裁剪、`truncated` 可见）、CLI 四命令
  （`ask` 确定性七词 / `status` / `session log` / `requirement add`）、Web Agent 面板。
- **M9 开发能力线**：`/dev`（语言知识点站位图 + 源码解读抽屉，多 provider、Keychain、
  出网同意与台账）与 `/resources`（学习资源清单）。
- **v0.2.3 批次 A**（发布解锁）：
  - **better-sqlite3 载入失败的可读诊断**：不再抛原始 ABI 堆栈，输出当前平台与架构、
    Node 版本与 ABI、三条修复路径；`sync --file` 等离线命令在原生模块损坏的机器上照常可用。
  - **复验矩阵工具**：`pnpm verify:matrix`（命令清单单源取 CLI_COMMANDS）。
  - **包名终裁**（见头部引言）。
- **v0.2.3 批次 E/F**（AI 问答与生态，M10 线）：
  - **`openvibe discuss "<问题>"`**：AI 问答通道——回答**逐段标注来源**（来源编号由服务端定，
    LLM 只能引用不能发明）；与 `ask`（确定性七词）并列互不影响；治理面与提取共用（总闸/逐项目同意）、
    预算独立。Web 工作台 AgentPanel 同款问块。
  - **`openvibe mcp`**：stdio MCP 服务——AI IDE（Claude Code/Cursor/Zcode 等）直接读取项目上下文：
    `project_context`（阶段/清单/任务/日志）、`search_assets`（术语/提示词/技巧检索）、`pack_diff`
    （注入漂移检查）。三工具全部只读、无网络监听；**依赖本地 serve 在线（离线场景本版不支持，
    serve 不可达时工具返回人话错误）**。
  - （批次 D 的提取闭环见上节「v0.2.3 批次 A」之后——提取/采纳率/成本台账已随 M10 线交付。）
- **v0.2.3 批次 B**（自证与度量）：
  - **`openvibe verify`**：包 / lock / 磁盘三方一致性只读核验，六态
    （CONSISTENT / PARTIAL / ORPHAN / DISK_DRIFT / STALE_LOCK / UNMANAGED），退出码 0/2/1；
    `sync` 注入前内置中断检测（lock 登记文件缺失即提示「上次注入可能中断」）。
  - **输出侧度量（OM1/OM2）**：`GET /api/om` + 设置页「输出侧度量」区——
    OM1 有效上下文密度（最新建包的受管 token ÷ 资产数，`?pack_id=` 可指定，Top5 按产物归因）、
    OM2 首次见效时间（台账首事件 → 首次注入的墙钟差）。全本机现算、零出网、不参与遥测；
    空数据如实显示「待采集」。

## AI 能力的出网清单（什么数据、在什么同意下、发给谁）

| 能力          | 触发                            | 出网内容                                              | 同意                                     | 留痕                                                           |

推理端点由你在设置页配置（本机 Ollama/LM Studio 或云端 API，密钥走 macOS 钥匙串）；本机端点不占出网预算。
AI 产出一律不直接入库：提取候选先进待确认队列（人工确认才落 draft 草稿），问答只读零写库。

## 已知局限（装之前就该知道）

- v0.1.0 已知局限的全部条目继续有效（一项目一包、整文件管理无块级合并、win32 门控 8 支、中文 UI、无团队协作）。
- **`verify` 的 STALE_LOCK 是版本级代理**：比对 lock 版本与服务端最新导出版本，
  不做渲染级逐文件比对（同版本不同内容的导出在库侧被 409 挡住，风险有限）。
- **OM1 密度缺省取最新建包**：若在用的主包不是最新建的，请用 `?pack_id=` 或界面读包名@版本。
